Track: technical

Scope boundary: Small fix for #1647, approved by the operator on 2026-09-06 (delegated). Replace FINISH's existence-only shipped-record observation with one that resolves the same canonical shipment identity the record writer resolves, and reports a present-but-wrong record as invalid so the already-written human-required disposition is reachable. Out of scope: the record's content or format, the premerge CI verifier and its refusal codes, backlog dedup, the second post-finish record refresh, the record's cost/timing rollups, and the duplicate-commit defect tracked separately as #1648.

This is an internal engine correction to an existing observation boundary; acceptance criteria live in technical stories rather than a PRD.

The operator's delegate weighed three candidates on 2026-09-06 and recorded the choice as approved by the operator on 2026-09-06 (delegated): (a) delete the unreachable branch — rejected, it cements the gap the branch was written to close and the issue asks for that to be an explicit decision, not a cleanup; (b) call the strict premerge verifier `evaluateShipmentEvidence` from the observer — rejected, it requires an implementation-PR head binding and a committed candidate tree, so it turns a filesystem observation into a GitHub round trip on every publication snapshot; (c) chosen — observe the working-tree record through the writer's own identity resolver and spec-hash function, so the observation costs one directory listing and three file reads and can never disagree with the writer about which record is this shipment's.

Two constraints from the approved decisions bound the chosen approach. The observation composes the strict verifier's own building blocks — `resolveShipmentIdentity`, `parseShippedRecord`, `parseStoriesReference`, `specHash` — rather than open-coding a second identity or hashing policy, because the fail-closed durable-shipment decision rejects separate engine and CI verifier implementations as policy drift at the seam it hardens. And `present` here remains an observation, never a terminal `valid` verdict: this boundary reads the working tree and compares slug and spec hash only, while `evaluateShipmentEvidence` — which additionally binds the record's PR, its presence in the candidate commit, and that commit's reachability from the implementation head — continues to gate terminal ship state unchanged.
