# Track: Compose the spec PR body with its release disposition

Track: technical

Scope boundary: Small fix for #1869, approved by the operator on 2026-09-06 (delegated). Make the spec-PR create call itself carry the release disposition, so the `opened` webhook payload the required check reads already declares one. Preserve the existing post-create repair as the degraded-path fallback, preserve the opt-in read from the target repository's own PR template, and preserve author-supplied declarations. Changing the check to re-read the live PR body, rerun/replay semantics, the implementation-PR disposition path, and the release PR renderer are outside this slice.

This is internal engineer-handoff tooling with no product requirement; acceptance criteria live in technical stories rather than a PRD.

Two approaches were weighed. (A) Compose the body before the PR exists, so the `opened` payload already declares the disposition — chosen. (B) Make the required check re-read the live PR body through the API instead of trusting the webhook payload — rejected: it does not remove the window (the check can still run before the repair edit lands), it weakens the check's immutable event-body contract that the shipped-record gate deliberately relies on, and it is a repository-CI change rather than a fix to the engine that creates the defect. The filer's hypothesis A won on merits, not by default. Est. effort ~1-2h; impact: every engineer-opened spec PR stops carrying a permanent red required-check entry, so a genuine disposition failure is legible without reading per-run history.

Scope check: A — consumer-facing. No repo-only signal fires: the change is in `src/conductor/src/engine/engineer/`, not self-host, not this repository's validation or release gates, not its CI, and not dependent on a convention only this repository has. `openSpecPr` runs against every repository in the engineer's registry, and the disposition contract is read from each target repository's own `.github/pull_request_template.md`, so a consumer repository that configures that contract benefits identically. The change is engine behavior only, so it registers no rule in either instruction file. B — n/a, no new skill. C — provider-agnostic: no provider path, environment variable, or host capability is named or relied on. Event spine: no event, metric, span, or report is added or changed.

Verified foundation. `handoff.ts` creates the PR with `runner(['pr','create','--head',branch,'--fill','--label','spec'])` and only afterwards calls `ensureReleaseMetadata`, which reads the body back with `gh pr view` and appends `DEFAULT_SPEC_RELEASE_BLOCK` via `gh pr edit`. `release-metadata-check-action.ts` parses `input.context.payload.pull_request.body` — the webhook payload snapshot, not the live body — so the `opened` event is evaluated against the autofilled body that carries no `## Release metadata` section, and `parseReleaseDisposition` throws `Invalid release disposition: Disposition`. `release-metadata-inject.ts` already owns the opt-in predicate `declaresReleaseDisposition`, the default block, and the author-wins rule, so composition belongs beside them. `land-spec.ts` writes the spec branch's tip commit as a single-line subject with no message body, so a body composed from that commit is byte-equivalent to what autofill produces today. `openSpecPr` already requires and uses a `gitRunner` for remote targets (it pushes the branch), so the commit message is reachable without a new dependency.
