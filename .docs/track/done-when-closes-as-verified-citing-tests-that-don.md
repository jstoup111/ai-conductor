# Track: Done-when `[test]` checks close as verified citing tests that don't assert the check (#3200)

Track: technical

Scope boundary: Balanced. Provenance split at task close: every task start path (`conduct task start` and the Claude Code session hook) records the task's start HEAD, and a `[test]` citation whose test title appears in lines added between that start commit and HEAD closes `verified` mechanically, exactly as today (no judge, no delay). Every other `[test]` citation (an untouched pre-existing test, or a stampless close with no recorded start) closes provisionally as pending judgement. Before BUILD hands off to review, the conductor dispatches one bounded, schema-constrained judgement (`asserts | does-not-assert`, with a reason) over the pending citations; `asserts` stamps a distinct judged close source, and `does-not-assert` reopens the task inside the same BUILD step with the judge's reason, so a refused citation returns to BUILD at close time rather than surfacing laps later through `prd_audit`. A reopened task does not count as resolved through its `Task:` trailers. After a hard per-check refusal bound, the outcome is never a lever-less halt: an operator-only `ai-conductor done-when accept` command (outside the daemon-session sanctioned list) unblocks the task and records the override as durable evidence. Provenance comes from the start→close window, never from `Task:` trailers (which stay telemetry, adr-2026-07-21); a test another concurrent task added inside the window counts as new. The judge runs in the conductor at the BUILD-completion boundary, not inside the `conduct task done` subprocess. Amends adr-2026-08-22-done-when-evidence-at-task-close (D6 text-only verification, D7 refusal handling, the closed close-record `source` set). Excluded: plan-skill authoring guidance for one observable outcome per check (#3194), projecting verified citations into `prd_audit`, judging tests the task itself added (a weak new test still closes mechanically), counterfactual test execution, re-enabling the retired `coverage_binding` step, and changing the `build_review` test-quality rubric's default.

Internal BUILD gate tooling with one operator CLI lever — no user-facing product capability; acceptance criteria come from #3200's desired outcomes and live directly in stories. Adds behavior, so not a maintenance change.
