# Track: Bound the build_review counterfactual scoped run to its deadline

Track: technical

Scope boundary: Small fix for #2177, approved by the operator on 2026-09-06 (delegated). Cover exactly the counterfactual scoped-run launch and termination path used by the build_review testQuality preflight: refuse to launch when the preflight deadline has already expired, and make an expired deadline terminate a running counterfactual before its outcome is reported. The preflight timeout value, the timer that owns it, the abort checkpoints inside the materializer, the aggregate test-suite runner, and every other spawn site in the engine are outside this slice.

This is an internal engine correctness fix with no product requirement; acceptance criteria live in technical stories rather than a PRD.

Two approaches were weighed. The filer's hypothesis — check `signal.aborted` before spawning and attach the signal to the spawn call — was taken only in part: the pre-launch guard is adopted, but attaching Node's `signal` spawn option is rejected because that path emits an `AbortError` on the child's `error` event, which the existing result mapping classifies as `scoped-run-launch-failed` rather than `scoped-run-timeout`, silently changing the recorded infrastructure-failure reason. The alternative not derived from the hypothesis — keep explicit termination control in the runner, add the pre-launch guard, and escalate SIGTERM to SIGKILL after a bounded grace before resolving — was selected because it preserves the existing reason mapping and additionally closes the orphaned-child case the hypothesis leaves open. Approved by the operator on 2026-09-06 (delegated).

Scope check: A — consumer-facing engine behavior (the counterfactual runner is engine code every installed project's build_review uses; no self-host, daemon, release-gate, or repository-local convention is involved); B — n/a (no new skill); C — provider-agnostic (no provider path, environment variable, or host capability is referenced). No catalog registration is required.

Verified foundation: `src/conductor/src/engine/step-runners.ts:2394-2419` spawns the counterfactual with `spawn('sh', ['-c', command])` and only then registers `signal.addEventListener('abort', …)`; an already-aborted signal never fires that listener, so the child has no kill path. `src/conductor/src/engine/step-runners.ts:2326-2328` arms the single `AbortController` from `test_suite.timeout_seconds`. `src/conductor/src/engine/build-review-test-quality-preflight.ts:398-438` checks `aborted(signal)` around most awaits, but the rename branch at line 419 and the added-path branch at line 426 `continue` after an await with no subsequent check, so the last materialized path can reach `runScoped` at line 438 with an expired deadline. `src/conductor/src/engine/build-review-test-quality-preflight.ts:319-327` maps a `timeout` result to `scoped-run-timeout` and a `launch-error` result to `scoped-run-launch-failed`. `StepRunnerOptions` already carries test-only injection points (`gitRunner`, `worktreeLifecycle`, `buildReviewCoordinator`), so a launcher seam follows the established constructor pattern rather than introducing a new one.
