Track: technical

Scope boundary: Pi `readOnlyReview` capability plus parity hardening only. In scope: (1) Pi declares the catalog-owned `readOnlyReview` capability, implemented as a harness-owned Pi extension (loaded with `-e` under `--no-extensions -na`) that registers a structured, shell-free read-only `git_read` tool, with Pi's tools restricted to `read,grep,find,ls,git_read` (no `bash`, `edit`, `write`), so Pi can be admitted to custom-policy build_review laps (once #1888 supplies `reviewPolicyCatalog`) under the existing input-digest discard backstop; (1b) Pi declares `nativeSchema` via a terminating `submit_result` tool in the same extension (Pi's documented structured-output pattern), added by operator decision 2026-09-29 because readOnlyReview is inert without it; (2) every unattended Pi dispatch passes `-na` (ignore project-local `.pi/` files, including a saved `~/.pi/agent/trust.json` decision) unless `llm_providers.pi.trust_project_files: true` deliberately enables it; operator-global `~/.pi` extensions keep loading on build dispatches (parity with claude plugins); (3) Pi dispatches get the same daemon env treatment codex gets (daemon-session marker, tmux scrub) instead of inheriting the raw daemon env; (4) environment-claim auditing stays correct for Pi (`osSandbox: false` from the catalog), covered by tests. Interactive operator Pi use outside the daemon is not newly restricted.
