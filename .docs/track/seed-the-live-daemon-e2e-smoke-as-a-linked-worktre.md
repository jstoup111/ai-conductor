# Track: Seed the live daemon E2E smoke as a linked worktree

Track: technical

Scope boundary: Small fix for #1669, approved by the operator on 2026-09-06 (delegated). Seed the shared live-provider daemon E2E run body as a main checkout plus a real linked worktree so build-review feature identity resolves on its own, drop the injected effective-verdict resolver from that run body, and keep the terminal-state assertions reading production-resolved locations. The scripted (non-live) sibling fixture's resolver stub, the disabled test-quality rubric, the reusable live workflow, and any change to production identity resolution are outside this slice.

This is repository test-infrastructure work on the opt-in smoke suite; acceptance criteria live in technical stories rather than a PRD.

Alternatives weighed: the filer's second hypothesis — an explicit test-only escape inside identity resolution — was rejected because it weakens the deliberate boundary that keeps one feature from consuming another feature's accepted-risk state, and because it would make the smoke pass through a code path production never takes. Seeding the production topology was chosen: it costs one `git worktree add` in a temp directory and makes the fixture exercise the real resolver.

Scope check: A — harness-repo-only (Step 1 signal 1: the fixture reproduces the daemon's worktree topology and the opt-in smoke that gates this repository's own releases); B — n/a (no new skill); C — provider-agnostic (the shared run body is the provider-neutral body both descriptor legs enter; no provider path, variable, or capability is touched). No catalog registration is required. The verdict agrees with the plain reading of the issue: the mechanism — the live release smoke and its temp fixture — exists only in this repository.

Verified foundation: `src/conductor/test/fixtures/live-e2e-run-body.ts:394` creates the fixture with a single `mkdtemp` and treats that directory as both repository root and project root; line 442 creates the feature branch with `git checkout -b` in that same directory; lines 468-478 inject a `buildReviewEffectiveResolver` that derives the verdict from the aggregate alone. `resolveBuildReviewFeatureIdentity` (`src/conductor/src/engine/build-review-effective.ts:57`) resolves the main root via `resolveMainRepoRoot`, realpaths both ends, and returns `undefined` unless the project root is exactly one path segment under the main root's `.worktrees/`; `resolveEffectiveBuildReviewVerdict` (same file, line 87) refuses with `build-review feature identity is unavailable` when it does. The disposition store reads `.pipeline/build-review-dispositions.json` under the project root (`src/conductor/src/engine/build-review-dispositions.ts:23,320`) and treats an absent file as an empty record set, so a freshly seeded worktree needs no seeded state. `isOperatorParked` (`src/conductor/src/engine/park-marker.ts:158`) resolves the main root before reading `.daemon/parked/<slug>`, which is why the run body's current worktree-local park check stops matching production once the fixture becomes a linked worktree.
