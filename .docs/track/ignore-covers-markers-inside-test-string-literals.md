# Track: Ignore Covers markers inside test string literals

Track: technical

Scope boundary: Small fix for #2597, approved by the operator on 2026-09-28 (option A). Read Covers marker comments from the parsed TypeScript syntax tree so text inside string and template literals can never become a marker, keep a genuinely unmarked test reported as unbound, and name each indeterminate candidate's test file and start line in the scope-incomplete HALT body. Desired outcome 2 (an unmarked test inheriting a file-level marker's obligations) is declined: it conflicts with adr-2026-09-06-engine-owned-test-quality-scope decisions 4 and 7, which keep file headers uncertain and unmarked tests unbound, and amending that approved ADR is outside a Small slice. The file-level-marker rules of that ADR are unchanged. Covers grammar, reviewer contract, projection version, and aggregate format are out of scope.

This is internal engine correctness work for the build_review test-quality rubric; acceptance criteria live in technical stories rather than a PRD.

Approach chosen over the filer's alternative readings: a parser-backed comment set (Option A) instead of teaching the standalone scanner to track template substitutions (it would re-implement the parser's template state) or string-stripping the source text (a regex over code cannot tell a quote inside a comment from a quote that opens a literal).

Scope check: A — consumer-facing (the test-quality rubric runs in every project that opts in; no self-host or repo-only machinery is touched); B — n/a (no new skill); C — provider-agnostic (pure engine parsing and HALT rendering). Event-spine: no new channel; the HALT reason already flows through the existing loop-halt emission.

Verified foundation: build-review-test-bindings.ts collects comments with ts.createScanner over the whole file text; a standalone scanner does not re-scan template continuations, so after a template substitution it treats template text as code. Run over the repository's own build-review-inputs.test.ts, that scanner reports a false comment at line 730 containing "// Covers: task:8" from inside a template literal and misses 63 of the 92 real comments the parser's comment ranges find. build-review-test-scope.ts turns introduced uncertain-association markers into candidates whose markers become obligation references in build-review-coordinator.ts, which is how the fragments reached the rubric. The scope-incomplete HALT in conductor.ts writes only the adjudication reason and trace, while deriveBuildReviewScopeIncompleteFault in build-review-domain.ts keeps each indeterminate candidate's sourceRegion path and startLine on the aggregate.
