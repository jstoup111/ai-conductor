# Track: Exempt Vitest's own temp dir from the tmpdir leak guard

Track: technical

Scope boundary: Small fix for #2759, approved by the operator on 2026-09-28 (delegated). The tmpdir leak guard's teardown diff stops counting the Vitest instance's own project temp directory as a leak when a run was launched without the package runner, and `scripts/run-vitest.mjs` resolves the package-local Vitest binary instead of relying on `node_modules/.bin` being on `PATH`. Changing the repository's `test_suite.scoped_command`, the run-root allocation in `scripts/vitest-temp.mjs`, the ignored-prefix list, and adding a fail-fast refusal for unredirected runs are outside this slice.

This is internal test-harness tooling; acceptance criteria live in technical stories rather than a PRD.

Approach choice, approved by the operator on 2026-09-28 (delegated): exempt Vitest's own directory by exact name rather than failing fast when `TMPDIR` was not redirected before Vitest started. The issue's first desired outcome requires a bare `npx vitest run <file>` to pass the guard, which a fail-fast refusal cannot deliver.

Scope check: A — harness-repo-only (the leak guard, `global-setup.ts`, and `run-vitest.mjs` exist only in this repository's conductor test harness); B — n/a (no new skill); C — provider-agnostic (no provider surface). No catalog registration is required. Event-spine: not applicable; the guard's existing teardown error and console report are test-harness output, not engine telemetry, and no new channel is introduced.

Verified foundation: `src/conductor/test/global-setup.ts` exports `setup()` with no parameter, snapshots the real tmpdir with `snapshotTmpdirEntries(originalTmpdir)`, and at teardown calls `applyTmpdirTeardownDecision(diffTmpdirEntries(tmpdirBefore, tmpdirAfter), originalTmpdir)`, which throws on any stray entry. `diffTmpdirEntries` in `src/conductor/test/tmpdir-leak-guard.ts` classifies every new top-level entry not matching `IGNORED_TMPDIR_PREFIXES` as stray. Vitest 4.1.11 sets `_tmpDir = join(tmpdir(), nanoid())` as a class field in `node_modules/vitest/dist/chunks/cli-api.CnMVyzaz.js`, passes it to the root `TestProject` as its public `tmpDir`, calls each globalSetup's `setup` with that project (`globalSetupFile.setup?.(this)`), and removes the directory later in `clearTmpDir`. `vitest.config.ts` installs the redirect only after that field is set, so a bare launch leaves the directory as a direct child of the real tmpdir. `src/conductor/scripts/run-vitest.mjs` spawns the bare command name `vitest`, which fails with `ENOENT` when `node_modules/.bin` is not on `PATH`; the fixture-level launcher tests live in `src/conductor/test/vitest-startup.test.ts` and the setup-with-mocked-guards lifecycle tests in `src/conductor/test/vitest-temp-lifecycle.test.ts`.
