# Track: daemon-commits-co-authored-by-the-configured-bot

Track: technical

Scope boundary: When a GitHub bot is configured (`github_bot.token_file`, spec #158), every commit the daemon creates carries a `Co-authored-by:` trailer naming the bot by its GitHub noreply address (`<id>+<login>@users.noreply.github.com`), so GitHub shows the operator and the bot as paired authors and the pairing survives the PR squash-merge. Covers build-agent commits made inside daemon-prepared worktrees and every engine bookkeeping commit the daemon makes (shipped record, shipped-record findings, halt record, remediation plan append, setup-triage quarantine/preserve/retain, shipment repair). The operator remains the commit author. The bot's login and id are derived from the bot token itself (the bot reading its own identity), cached per daemon run, with no new config key. If the identity cannot be resolved, the trailer is skipped and a warning is emitted through the canonical ConductorEvent spine; the commit is never blocked. The bot token never appears in any commit message, event, or log. With no bot configured, daemon commits are byte-for-byte unchanged. Excluded: commits made by operator-run CLIs (`compose land` spec commits, `engineer land`), manual operator commits, changing the git author or committer identity, composing the squash-merge message, GitHub App installation tokens, and a co-author override config key.

Rationale: engine commit-attribution plumbing on existing hook and commit seams with operator-only visible effects — acceptance criteria belong in stories, no PRD.
