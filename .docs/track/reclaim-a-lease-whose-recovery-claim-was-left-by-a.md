# Track: Reclaim a lease whose recovery claim was left by a dead process

Track: technical

Scope boundary: Small fix for #2170, approved by the operator on 2026-09-06 (delegated). Inside the slice: the conduct-state lease's already-held recovery-claim branch — inspecting an existing claim, proving its writer dead before reclaiming it, refusing an invalid or unverifiable claim, naming the real blocking state in the acquire timeout, and keeping two concurrent recoverers mutually exclusive. Outside the slice: the separately filed full-suite lock carrying the same defect pattern, the owner-metadata read path (owned by the in-flight sibling spec for #2172), wait-budget or retry-delay defaults, claim expiry by wall-clock age, pid-recycling hardening beyond the module's existing liveness probe, and every lease call site.

This is an internal engine correctness fix with no operator-facing flag, message contract, or configuration surface of its own; acceptance criteria live in technical stories rather than a PRD.

The operator approved reclaiming through the existing atomic directory move rather than unlinking the stale claim file, on 2026-09-06 (delegated). Unlinking a claim by path reintroduces the race it is meant to close — two recoverers can both observe the same dead claim, and the slower one's unlink would delete a freshly written live claim. Adopting the proven-dead claim as the recovery authority and letting the existing directory move arbitrate keeps the module's rule that exclusion is decided by an atomic filesystem operation, never by a read-then-write window.

Scope check: A — consumer-facing engine behavior, because the lease ships in the conductor engine and guards every consumer's state mutation; it changes no harness rule, no documented message, and no configuration key, so no `HARNESS.md` or `docs/` page is owed. B — n/a (no new skill). C — provider-agnostic; the lease is filesystem machinery with no provider, model, or host coupling. No catalog registration is required.

Verified foundation: `conduct-state-lease.ts` proves an owner dead through an injected liveness probe, then writes an exclusive recovery claim; the branch that handles an already-existing claim returns straight to the acquire loop without reading, parsing, or liveness-checking that claim, and reports the proven-dead owner's pid as the live blocker in the acquire timeout message. The module already carries every part the fix needs: a metadata validator and parser pair for the owner record, the injected liveness seam, an absence helper, an atomic quarantine move to a per-process destination, and a diagnostic callback whose refusal reasons are its existing observability channel. Only the lease's own unit tests subscribe to that callback, so its union can gain members without touching a production consumer.
