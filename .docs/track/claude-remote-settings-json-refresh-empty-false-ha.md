# Track: Claude remote-settings.json empty-to-{} refresh false-halts self-host builds (#3096)

Track: technical

Scope boundary: Minimal, one file. Make the Claude provider-state fingerprint treat a semantically empty root `remote-settings.json` (zero bytes, whitespace only, or JSON that parses to an empty object) as one equivalent content state, so a refresh that flips it between empty and `{}` does not halt a self-host build. The file stays in the manifest: real managed-settings content changes, creation, and deletion still halt and name the file. Excluded: widening any volatile/exclusion list (CLAUDE.md daemon rule 5), content-aware exclusion in general, normalization for any other provider-state or live-checkout file, Codex or Pi provider homes, changes to halt attribution (#1301), and changes to the halt-reason format.

Rationale: internal self-host guard behavior with no user-facing requirements; acceptance criteria live in stories. Approved approach: per-provider "semantic-empty JSON" path table consulted when digesting a manifest entry, so empty and `{}` share one canonical digest while the path stays fingerprinted. Rejected: content-aware exclusion while the file parses as `{}` (drops the entry from the manifest, so creating or deleting an empty file would vanish from the diagnosis, violating the third desired outcome); post-diff amnesty comparing before/after digests against a fixed set of known-empty byte digests (needs a second classification pass on the provider surface and only matches exact byte forms such as `{}` without a trailing newline).
