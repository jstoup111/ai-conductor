# Track: Run memory-store setup on daemon dispatch

Track: technical

Scope boundary: Small fix for #2062, approved by the operator on 2026-09-06 (delegated). Establish the canonical per-project memory store on the daemon's worktree-preparation path, idempotently and without aborting the dispatch on failure, and report the resulting placement on the existing event spine. Memory read paths, provider selection, the write-fallback/reconcile design, the migration algorithm itself, and any change to the inline prelude's behaviour are outside this slice.

This is an engine defect correction on a shipped daemon path; acceptance criteria live in technical stories rather than a PRD.

The filer's second hypothesis is resolved by reading rather than by decision: `projectKey` derives identity from `git remote get-url origin`, falling back to `git rev-parse --git-common-dir`, both of which are identical for a linked worktree and its root checkout, so a worktree and its root checkout already resolve to the same store. No per-worktree keying question remains open, and no design decision is deferred.

Verified foundation: `dispatchMemorySetup` in `src/conductor/src/engine/memory-cli.ts` migrates a real `.memory/` directory through `migrateMemory` and otherwise calls `ensureMemoryStore`, both idempotent, returning 0 or 1 and printing to the console. Its only caller is `runProjectPrelude` in `src/conductor/src/engine/project-prelude.ts`, which is itself called only from `src/conductor/src/index.ts` — the inline path. The daemon's worktree preparation is bound in `src/conductor/src/engine/daemon-deps.ts` and runs on every dispatch from `src/conductor/src/engine/daemon-runner.ts`, and neither it nor `src/conductor/src/engine/worktree-prepare.ts` mentions the memory store. `ensureMemoryStore` in `src/conductor/src/engine/memory-store.ts` creates the canonical directory and replaces a stale `.memory` symlink but never touches a real directory; `migrateMemory` in `src/conductor/src/engine/memory-migrate.ts` copies, verifies, and swaps, leaving an ignored `.memory.pre-migrate.bak` backup and calling `ensureBackupIgnored` idempotently. The `ConductorEvent` union in `src/conductor/src/types/events.ts`, the exhaustive `EVENT_SINKS` map in `src/conductor/src/engine/event-sinks.ts`, and the `renderDaemonEvent` switch in `src/conductor/src/daemon-cli.ts` are the three places an added variant must be registered; persistence is derived from the sink map by `src/conductor/src/engine/event-persister.ts` and needs no separate wiring.
