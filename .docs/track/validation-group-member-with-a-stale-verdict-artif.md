# Track: Validation-group member with a stale verdict artifact re-dispatches instead of remediating

Track: technical

Scope boundary: Engine-only, narrow (pre-authorized autonomous run; recorded here as the binding breadth). A validation-group member (`manual_test`, `prd_audit`, `architecture_review_as_built`) whose dispatch settles successfully but whose post-dispatch verdict write handshake reports no current verdict (missing, stale, prior-identity, or incomplete output — `routeClass: 'absent'`) is re-dispatched inside its own branch within its resolved `max_retries`, and on exhaustion settles `no-verdict` so the existing no-verdict join halt names the handshake failure. Included: the branch retry loop in `group-core.ts`, the validation-group wiring in `conductor.ts`, and the existing `step_retry` event's `reason` naming the handshake failure. Excluded: the serial SHIP-tail path (already reruns per adr-2026-08-25 D5), the DSL `runParallelGroupViaCore` path (its members are not verdict steps), the FINISH publication fence, remediation planner dispositions, any new event variant, config key, or HALT class, and any change to how a present-but-unsatisfied verdict is routed.

Approaches weighed (filer hypothesis entered as one candidate, not privileged):

- A (filer hypothesis): keep the branch as-is and teach the join to treat a handshake-failed `verdict: pass` member as no-verdict and re-dispatch it in a join-level retry round, like the auth-recovery redispatch loop. Rejected: it adds a second retry ladder beside `runGroupBranch`'s own budget, so attempt accounting would be split across two places and the "bounded" budget would need new bookkeeping.
- B (selected): fold the existing handshake into the branch's own attempt loop through an injected verification hook. A successful runner result whose handshake reports an absent verdict is an ordinary failed attempt: it consumes the member's resolved `max_retries`, re-dispatches with a fresh dispatch start, and on exhaustion returns `no-verdict` carrying the handshake reason. One budget, one exhaustion path, and it is exactly adr-2026-08-25-engine-stamped-ship-tail-verdict-run-identity D5 ("absent → rerun within the existing step-retry budget; on exhaustion a `needs-human` halt naming the artifact and identities") applied to the group branch, matching the serial path.
- C: add a remediation disposition that re-runs the audit. Rejected: it routes a mechanical fact (this dispatch wrote no current verdict) through an LLM planner, spends a kickback lap, and contradicts adr-2026-07-10-validation-group-join D2 ("No synthetic gaps are invented" for a no-verdict branch).

Internal engine behavior with no product requirements; acceptance criteria live in stories (intake jstoup111/ai-conductor#2553).
