# Track: Accept trailing-hyphen slugs in compose handoff

Track: technical

Scope boundary: Small fix for #2697, approved by the operator on 2026-09-28 (delegated). Make the spec-branch check used by `compose handoff` accept every slug the engineer slug generator can produce, including a truncated slug that ends in a hyphen, by defining that slug grammar once beside the generator and having the handoff check consume it. Branches that are not `spec/<slug>`, have an empty slug, or carry a slug the generator can never produce keep the current refusal and message, before any remote mutation. Changing the generator's output (for example trimming a trailing hyphen after truncation), renaming existing stems or branches, and every other slug consumer are outside this slice.

This is an internal engine correction; acceptance criteria live in technical stories rather than a PRD.

Approach decision (approved by the operator on 2026-09-28, delegated): widen the handoff grammar to the generator's real output instead of trimming the generator. The issue requires existing trailing-hyphen stems and branches to keep working, so the handoff grammar must accept them in either design; trimming the generator would additionally change the slug of any idea whose truncation ends in a hyphen, which `compose land` re-derives from the same idea text, so it is left out.

Scope check: A — consumer-facing engine behavior: no repo-only signal fires and the engineer compose CLI ships to every installed repository; no rule or documentation placement changes; B — n/a (no new skill); C — provider-agnostic (no provider code touched). No catalog registration is required. Event-spine: no event, metric, span, log line, or report is added or changed.

Verified foundation: `src/conductor/src/engine/engineer/spec-branch.ts` `slugify` lowercases, collapses every non-alphanumeric run to one hyphen, strips leading and trailing hyphens, then slices to 50 characters, so its output is empty or matches lowercase alphanumeric words joined by single hyphens with at most one trailing hyphen and at most 50 characters. `worktree-authoring.ts` builds the branch as `spec/` plus that slug and `land-spec.ts` re-derives the stem with the same `slugify`. `src/conductor/src/engine/engineer-cli.ts` `featureMarkerForSpecBranch` matches `/^spec\/([a-z0-9]+(?:-[a-z0-9]+)*)$/`, which rejects a trailing hyphen, and throws `engineer handoff: branch "<branch>" is not a canonical spec/<slug> branch.`; it is called from the exported `initialSpecPublication`, which the `handoff` CLI case constructs before `openSpecPr` pushes or creates a PR. No other production code validates the spec-branch slug.
