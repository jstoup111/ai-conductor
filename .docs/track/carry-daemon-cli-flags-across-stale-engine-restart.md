# Track: Carry daemon CLI flags across stale-engine restart

Track: technical

Scope boundary: Small fix for #2366, approved by the operator on 2026-09-28 (delegated). The session-hosted stale-engine self-restart rebuilds the pane command from config alone, so every run flag the operator passed to the `daemon` command is dropped on the respawn. This slice captures the run flags the daemon parser already recognizes and replays them, shell-quoted, onto the respawned command. Because the respawned process receives the flags on its own argv, it captures and replays them again at its next restart, so the flags govern the whole process lineage and concurrency provenance keeps reporting `source flag`. The operator-issued `daemon start` and `daemon restart` verbs, bare-run (non-tmux) restarts that exit instead of respawning, persisting settings beside the pid record, and new daemon flags are outside this slice.

Approach decision (conventional, approved by the operator on 2026-09-28 (delegated)): replay the parsed argv flags rather than persist resolved settings beside the pid record. Replay keeps the existing argv-to-options parser as the single source of truth, needs no new file or schema, and matches the issue's first hypothesis. The desired outcome's fallback clause (report a setting that cannot be carried) has no remaining case: every flag that `detectDaemonCommand` reads for a daemon run is carried, so no fallback message is introduced.

This is internal engine tooling; acceptance criteria live in technical stories rather than a PRD.
