# Track: Mechanically enforce OTel handler coverage for traced events

Track: technical

Scope boundary: Small residue of #1490, approved by the operator on 2026-09-06 (delegated). Bind the OTel visualizer's per-event routing to the single sink declaration so an event declared traced cannot be subscribed and then dropped, and make an unroutable traced event report itself instead of vanishing. Excluded: widening the traced set, adding new event variants, changing span or metric shapes, and any change to the exporter, transport, resource, or config surfaces.

This is an internal engine correctness guard for an existing telemetry surface; acceptance criteria live in technical stories rather than a PRD.

Three of the issue's five desired outcomes are already delivered on origin/main and are explicitly out of scope here. PR #1973 (commit 5ca39d4f8) added the `otel` column to `SinkDeclaration`, added `otelEventTypes()`, and replaced the visualizer's hardcoded subscription array with a loop over that accessor. PR #1997 (commit 847a1ad96) added `SpanManager.onLoopHalt` and the `complete | halted | terminated` run-outcome taxonomy, so a halted run is distinguishable from one in progress, and `forceCloseAll()` closes every remaining step span as `conductor.incomplete` before the flush. What remains undelivered is the first outcome's mechanical guarantee: subscription is derived, but `handleEvent`'s `switch` is a second hand-maintained list, so declaring `otel: true` without adding a case yields a subscribed event that is silently discarded. The fifth outcome — excluded events stay excluded as a recorded decision — is preserved rather than changed, and is carried here only as a regression guard.

The operator-delegate chose compile-time derivation over a test-only parity assertion on 2026-09-06 (delegated). A parity test catches the drift one suite run later; a mapped-record handler table keyed by the sink table's literal `otel` values rejects it at `tsc`, at the moment of the mistake, which is this repository's stated default. A runtime warning is retained as the floor for the case where the registry is consulted at runtime and the two can still disagree.

Scope check: A — consumer-facing (shipped engine code; no self-host, daemon, CI, or `.docs`-layout dependency), delivered as engine code, so no `HARNESS.md` rule and no documentation page changes; B — n/a (no new skill); C — provider-agnostic (no provider is named or branched on). No catalog registration is required.

Event-spine check: no new channel. The change adds no watcher, poller, sidecar file, bespoke log, artifact timestamp, or IPC path; it constrains how the existing bus's OTel sink routes events it already receives, and the unhandled-type report reuses the visualizer's existing injected `onWarning` callback. The skill's step 1 does not fire, so no ADR is required.

Verified foundation: `event-sinks.ts` declares `EVENT_SINKS` as `Record<ConductorEvent['type'], SinkDeclaration>` with a fourth `otel` column, and `eventTypesFor('otel')` backs `otelEventTypes()`. `otel-visualizer.ts` imports `otelEventTypes` and subscribes from it in `start()`, but dispatches through a sixteen-case `switch` in the private `handleEvent`; the two lists agree today and nothing enforces that. `test/event-sink-registry.test.ts` already proves with `@ts-expect-error` that every union member needs a declaration, which is the pattern this work extends. `tsconfig.test.json` type-checks `test/` as well as `src/`, so a compile-time assertion written in a test file is checked by `npm run typecheck:test`. TypeScript is pinned at 6.0.3 and `as const satisfies` is already used in `live-e2e-providers.ts`, `config.ts`, `model-table-metadata.ts` and `closeout-cli.ts`.
