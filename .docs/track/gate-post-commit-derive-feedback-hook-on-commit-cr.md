# Track: Gate the post-commit derive-feedback hook on commit-creating Bash commands

Track: technical

Scope boundary: Small fix for #2162, approved by the operator on 2026-09-06 (delegated). Confine the change to the hook script's own early-exit logic so the engine derive invocation and its advisory warning happen only after a Bash command that actually created a commit, and update the hook's reference row. The hook's settings wiring, matcher, timeout, warning text, engine contract, bash fallback, and the `AI_CONDUCTOR_ENGINE_BIN` override stay exactly as they are. Wiring the existing hook test script into the integrity suite, and any change to `bin/install` or the settings schema, are outside this slice.

This is an internal developer-tooling latency correction with no product requirement; acceptance criteria live in technical stories rather than a PRD.

The operator-delegated choice on 2026-09-06 was a stdin-payload command gate over a stamped last-seen-sha sidecar. The filer offered both. The sidecar was rejected because it introduces a durable per-repository file whose only reader is the hook, and it also fires after a plain `git checkout` that moved HEAD without creating anything; the payload gate needs no new state, exits before the hook touches Git at all, and is refined by a HEAD-freshness test that costs nothing on the common path.

Scope check: A — consumer-facing (the hook installs into every consumer repository through `bin/install`, and a repository with no daemon and no `.docs/` history gets the same latency relief), so the reference documentation stays under `docs/reference/`; B — n/a (no new skill); C — no new provider asymmetry: the change stays inside the existing Claude-host `PostToolUse` hook seam, and Codex's lack of an equivalent PostToolUse seam predates this slice and is unchanged by it.

Verified foundation: `hooks/claude/post-commit-derive-feedback.sh` reads no standard input at all — it goes straight to `git rev-parse HEAD` and then to `timeout 5s "$engine_bin" derive-feedback --sha "$commit"`, so every `PostToolUse`/`Bash` firing pays the engine spawn and re-prints the same warning. `bin/install` registers it under the `PostToolUse` matcher `Bash` with a 15-second timeout, so the host calls it after every Bash tool use. `hooks/claude/docs-guard.sh` already establishes this repository's bounded-payload read (`timeout 3 head -c 1048576` with a fail-open empty result), and `hooks/claude/block-destructive-git.sh` already establishes both the `tool_input.command` extraction through `python3` and the quoted-span-stripped "scannable copy" used to keep a quoted mention from triggering. `src/conductor/src/engine/self-host/release-gate.ts` classifies any path under `hooks/` as the canonical `hook wiring` breaking surface, so the implementation diff carries an internal-only release waiver rather than an invented migration block.
