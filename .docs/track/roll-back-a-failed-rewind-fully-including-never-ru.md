# Track: Roll back a failed rewind fully, including never-run steps

Track: technical

Scope boundary: Small fix for #2181, approved by the operator on 2026-09-06 (delegated). Scope is the operator `rewind` command's failure path in the engine's rewind module: restoring step fields that had no recorded status before the rewind, restoring the gate verdicts the rewind removed when the halt clear fails, and reporting the original failure ahead of any rollback failure. The successful rewind's demotion set, its target status, its clearing order, and the operator-only authority of the verb are unchanged. Automatic recovery, a new operator flag, resumable partial rewinds, and any redesign of the state mutation port are outside this slice.

This is an internal engine correction to an existing operator command; acceptance criteria live in technical stories rather than a PRD.

The operator-delegated decision on 2026-09-06 was to restore absent fields through the state store's existing explicit field-deletion authority rather than to stop demoting never-run steps. Narrowing the demotion set would change which steps a successful rewind demotes, which the approved operator-rewind decision record fixes as the target step plus every non-skipped step after it; the rollback fix leaves that decision untouched and repairs only the recovery path.

Scope check: A — consumer-facing (the `ai-conductor rewind` command and the engine state store ship to every repository that installs the harness; no self-host, release-gate, CI, or repository-local convention signal fires); B — n/a (no new skill); C — provider-agnostic (no provider, model, or prompt surface is involved). No catalog registration is required. Event spine: no channel is added — the rewind's success event is unchanged, a fully rolled-back failure leaves no durable state change to report, and the transient renames used to make gate-verdict clearing reversible are the same files under the same reader, deleted or restored inside the one call.

Verified foundation: in the worktree, `src/conductor/src/engine/rewind.ts:268-271` builds the demoted set from `steps.slice(targetIndex)` filtered only on `!== 'skipped'`, so a step with no recorded status is demoted to `stale`; `rewind.ts:157-159` then throws `Cannot restore absent rewind field` on the first such step, aborting the whole rollback; `rewind.ts:140-143` deletes the demoted steps' gate verdict files before `clearHaltAtomically`, so a halt-clear failure has already destroyed them; and `rewind.ts:216-226` prints the rollback failure before the original failure. The repair mechanism already exists: `src/conductor/src/types/state.ts:113-128` defines `StateFieldDeletion` and `PrivilegedStateCorrection`, `src/conductor/src/engine/conduct-state-store.ts:28` exposes the optional `applyCorrection`, and `src/conductor/src/engine/filesystem-conduct-state-store.ts:223-258` implements it with a deletion guard that accepts an already-absent field. `src/conductor/src/engine/rewind.ts:68-131` is the in-repository precedent for stage-then-delete clearing that restores what it moved when the operation fails.
