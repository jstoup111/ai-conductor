# Track: Qualify the reported cost figure when it covers only metered dispatches

Track: technical

Scope boundary: Small fix for #1863, approved by the operator on 2026-09-06 (delegated). Change only how the whole-feature finish usage line presents its money figure: name the dispatch count the dollars were summed over whenever that count is below the run's dispatch count, keep the line unchanged when every dispatch carried a cost, and withhold the money figure entirely when nothing was cost-metered. The rollup arithmetic, the event payload, the per-dispatch provider lines, the shipped-record Cost block, the cost CLI aggregates, and the existing exclusion segments are all outside this slice. No dispatch acquires an estimated or extrapolated cost.

This is an internal reporting correction with no product requirement behind it; acceptance criteria live in technical stories rather than a PRD.

Approach chosen over two alternatives, approved by the operator on 2026-09-06 (delegated). Rejected: always printing the denominator, which adds ceremony to the ordinary fully-metered line the issue explicitly asks to leave alone. Rejected: adding a `costMeteredDispatches` field to the rollup projection and the event payload, which widens the event schema for a quantity that is already derivable from the two counts the payload carries. The filer's own hypothesis — presentation-only, qualify only when the denominators disagree — won on merits.

Scope check: A — consumer-facing (the finish usage line ships in the engine and is rendered by both the daemon CLI and the terminal renderer in any repository that installs the harness; no self-host, release-gate, CI, or repo-convention signal fires); B — n/a (no new skill); C — provider-agnostic (the line names no provider-specific path, variable, or capability, and the metering classification already treats every provider identically). No catalog registration is required. Event spine: no channel is added — the change renders fields the existing `feature_usage_total` event already carries, so no union member, sibling ledger, or ADR is needed.

Verified foundation: `formatFeatureUsageTotal` in `src/conductor/src/execution/provider-diagnostics.ts` gates both the money figure and the token figures on `meteredDispatches > 0` and appends the cost-unmetered and unmetered segments after them. `toFeatureUsageTotals` in `src/conductor/src/engine/cost-rollup.ts` derives `meteredDispatches` as `dispatches - unmetered.count` clamped at zero and carries `costUnmeteredDispatches` from `rollup.costUnmetered.count`. `addDispatch` in the same file adds `costUsd` only when `classifyMetering` returns `fully-metered`, so the dollars are summed over exactly `meteredDispatches - costUnmeteredDispatches` dispatches — a quantity present on the line's input and never printed. `classifyMetering` in `src/conductor/src/engine/metering.ts` returns `fully-metered`, `cost-unmetered`, or `unmetered` and invents no cost. The line reaches operators through `renderDaemonEvent` in `src/conductor/src/daemon-cli.ts` and the terminal renderer in `src/conductor/src/ui/terminal-renderer.ts`, both of which pass the event straight to the formatter.
