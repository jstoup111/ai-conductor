# Track: Destructive-git guard parser misses valid git and bash spellings

Track: technical

Scope boundary: Both guards — the engine PATH git guard (`GIT_GUARD_SCRIPT` in `src/conductor/src/engine/git-hook-assets.ts`) and the shipped Claude hook (`hooks/claude/block-destructive-git.sh`) — normalize git's full option grammar for the guarded subcommands (reset, branch, clean, push, checkout, restore): git global options before the subcommand, unique-prefix long-option abbreviation, bundled short flags, `--no-` negation, `--`, and `+refspec` force pushes; any option token a guarded subcommand's spec does not recognize after normalization is refused (fail closed). One shared table-driven corpus is run against both guards, and a drift test checks each spec against `git <cmd> --git-completion-helper`. Excluded: shell indirection in the Claude hook (`$var` git, `eval`, `bash -c "…"`), which the hook already accepts as out of scope and the PATH guard covers in self-host.

Guard hardening with no new user-facing capability; acceptance criteria live in stories. Operator confirmed 2026-10-03. Chosen approach: fail-closed normalizer with a shared corpus (filer's delegate-to-git hypothesis rejected: `--git-completion-helper` omits `--force` for clean and branch on git 2.53.0, and git cannot parse a builtin's options without running it). The three originally reported bypasses (d4 prefix, d5 `--config-env=`, d8 heredoc quote removal/comment openers) are already fixed on main by #2773; verified residual bypasses: `reset --har`, `branch -df`, `branch --delete --forc` (both guards), and global-option prefixes, `clean -xdf`, `push origin +main` (Claude hook). Source: jstoup111/ai-conductor#2904.
