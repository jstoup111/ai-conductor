# Track: Render every declared render event in inline runs

Track: technical

Scope boundary: Small fix for #2167, approved by the operator on 2026-09-06 (delegated). Derive the inline terminal subscriber's subscription from the event-sink registry instead of a hand-maintained array, give the inline dashboard renderer dedicated lines for the halt, kickback, gate-verdict and convergence events an operator needs, and give every other event declared renderable a one-line fallback so an inline run is never silent about a renderable occurrence. Unifying the two overlapping inline renderers, widening what the daemon forwards to its terminal renderer sink, changing any sink declaration, and reworking the OTel sink (tracked separately as #1490) are outside this slice.

This is an internal terminal-UI correction in the shipped engine; acceptance criteria live in technical stories rather than a PRD.

The operator-delegated decision on 2026-09-06 was to prefer a derived subscription plus a generic fallback over authoring forty-five bespoke render branches. Bespoke branches for every renderable type would be a multi-day mechanical rewrite and would re-introduce the same drift the issue reports; a derived subscription plus a fallback makes coverage total by construction, and the four operator-critical events keep purpose-written lines.

Event spine: Channel? no — this consumes the existing `ConductorEventEmitter` bus and the existing `EVENT_SINKS` declarations. Concern: occurrence, already carried by the bus. Verdict: no new channel and no new union member; a bus consumer is corrected to read what the bus already publishes. Exception: none needed.

Scope check: A — consumer-facing (a repository with no daemon and no `.docs/` history runs `ai-conductor inline` and gets the same silent halt today), so the change lands in the shipped engine under `src/conductor/`; no behavioral rule file changes. B — n/a (no new skill). C — provider-agnostic (terminal rendering is independent of the selected LLM host). No catalog registration is required.

Verified foundation: `src/conductor/src/ui/subscriber.ts:27-54` holds a 27-entry hand-written array and `:59-64` forwards only `halt_marker_write_failed`, `renderer_error` and `pipeline_tail_diagnostic` to the injected `UIRenderer`. `src/conductor/src/engine/event-sinks.ts` declares 62 types `render: true`, and `renderedEventTypes()` at `:145` is the accessor the daemon feature bus already uses at `src/conductor/src/daemon-cli.ts:1147`. `src/conductor/src/ui/create-renderer.ts:97-306` switches on 24 event types and has no branch for `loop_halt`, `kickback`, `gate_verdict` or `loop_converged`; `src/conductor/src/ui/terminal-renderer.ts` does have those four branches but the inline path never routes them to it. `src/conductor/src/index.ts:1091` builds one live region and passes it at `:1369` into both the `createRenderer` callback (`:1373`) and, through `registerCliBuiltins` (`:1384`) and `registerBuiltins` in `src/conductor/src/engine/plugin-loader.ts:227`, into the `TerminalRenderer` — so the two inline renderers write to the same region and a fallback that overlapped the forwarded three would print twice.
