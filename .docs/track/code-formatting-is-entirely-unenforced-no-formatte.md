# Track: Enforce canonical code formatting on touched files

Track: technical

Scope boundary: TypeScript (src/conductor and plugins/) and shell (.sh and bash-shebang) files only. In scope: a pinned formatter configuration plus `.editorconfig`; one command that produces the canonical form for touched files or for the whole repository; a `format:check` command, run like `typecheck`, that fails when any TypeScript or shell file changed against the base reference is not in canonical form, enforced both as a CI job and as a self-host `test_suite` command. Out of scope: any change to `hooks/claude/lint-after-edit.sh` or other consumer-shipped surfaces (the change is harness-repo-only), a whole-repository reformat commit (the operator runs the whole-repository command manually when the daemon queue is empty), any rebase machinery for carrying in-flight branches across a reformat, Markdown/JSON/YAML formatting, and any ESLint style rule (the errors-only ESLint stance is unchanged). Files a pull request does not touch are not checked; that narrowing of the issue's outcome is operator-accepted.

Internal developer tooling (formatter + CI gate) with no user-facing product requirements; acceptance criteria live in stories. Operator confirmed 2026-11-07. Chosen approach: touched-files enforcement. Rejected: a whole-repository reformat now (measured 2,294 of 2,562 TS files rewritten, ~465 of the 612 TS files touched by 107 in-flight branches would conflict) with or without format-rebase carry-over machinery (judged wasted work against a manual sweep at an empty queue), and directory-sharded reformat behind an allowlist (retire-later machinery). Source: jstoup111/ai-conductor#1991.
