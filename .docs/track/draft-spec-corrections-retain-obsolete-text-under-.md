# Track: Draft spec corrections retain obsolete text under amendment policy

Track: technical

Scope boundary: Fix for #2499, decided by the operator before DECIDE (delegated, 2026-10-09). A DECIDE artifact absent from the base branch is still a draft: DECIDE revises it in place, removing superseded text, and adds no amendment note. The additive amendment note applies only to non-story DECIDE artifacts already present on the base branch. Scope is that lifecycle distinction in the consumer-facing rule (`HARNESS.md` "DECIDE Artifact Amendment Ownership"), its restatements in the shipped DECIDE skills that instruct an amendment note (`conflict-check`, `architecture-review`, `coherence-check`), and one mechanical land gate in `ai-conductor compose land` that refuses an amendment note in a `.docs/` artifact absent from the base branch. The story-artifact in-place rule, the additive form for on-base artifacts, the BUILD prohibition, the protected-target scan, coverage binding, and the reseal procedure stay exactly as they are.

This is harness behavior with no end-user product surface; acceptance criteria live in technical stories rather than a PRD.

Approach chosen: rule text plus a land gate, per this repository's "machinery by default" design principle. Whether an artifact exists on the base branch is a mechanical fact (`git ls-tree` at the merge base), so the distinction the issue asks agents to make is enforced at the point of violation instead of resting on prompt discipline alone. Rejected alternative: prose-only change — it leaves the same drift path that produced the observed session. Rejected alternative: teach coverage binding to ignore amendment blocks in new files — it hides the obsolete text instead of refusing it, and the issue's desired outcome is an artifact holding only current scope.

"Base branch" means the target repository's default branch, normally `main`, as resolved by `deriveDefaultBranch` and the `merge-base HEAD <default>` the land primitive already computes. An artifact this spec branch already committed (for example a prior land of the same spec) but that is not yet on the base branch is still a draft and is revised in place.

Scope check (`.agents/skills/scope-check/SKILL.md`): A — consumer-facing. No repo-only signal fires: the change touches no self-host, daemon, sandbox, release-gate, CI, or repo-only `.docs/` convention. The mechanism the rule describes — DECIDE-owned correction of accepted DECIDE artifacts, the shipped DECIDE skills, and the `ai-conductor compose land` gate — exists in every consumer repository that runs DECIDE, so the rule lands in `HARNESS.md`, not `AGENT_INSTRUCTIONS.md`. B — n/a (no new skill). C — provider-agnostic (rule prose, shipped skill prose, and an engine land gate; no provider path, variable, or capability is touched).

Event spine: no new channel. A refusal raises a new `LandGateIdentifier` value, which the existing `land_gate_rejected` event already carries through `classifyLandGateRejection` (`src/conductor/src/types/events.ts:483-490`).

Ordinary documentation (`docs/reference/artifacts.md:239-249`, `docs/runbooks/stalled-or-stuck-feature.md:868-873` and `:1047-1057`) restates the additive form; per the plan skill's documentation boundary it is not plan work and is owned by this repository's `maintain-documentation` custom step.

Verified foundation:

- `skills/conflict-check/SKILL.md:209-221`, `skills/architecture-review/SKILL.md:51-62`, and `skills/coherence-check/SKILL.md:268-271` each restate the additive form without that distinction. `skills/stories/SKILL.md:171-181` already replaces in place and needs no change.

No existing gate inspects artifact text for amendment notes.
