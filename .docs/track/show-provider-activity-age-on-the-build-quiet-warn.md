# Track: Show provider activity age on the build quiet warning

Track: technical

Scope boundary: Small fix for #1815, approved by the operator on 2026-09-28 (delegated). This re-specs the slice first proposed in closed spec PR #2340, which was withdrawn only because it would have overlapped #1715; #1715 has since shipped (the quiet warning now carries and renders the last commit time), and this slice builds on that result. The build-progress watcher already holds every fact it needs except one that sits unread on disk: the provider-activity heartbeat the running dispatch stamps into the build worktree. Carry the newest such pulse's timestamp on the quiet-episode event the watcher already emits, and name its age on the daemon warning line that already renders that event. The quiet threshold, the heartbeat's own write cadence, the periodic build-progress heartbeat tick, the post-hoc stall breaker, the interactive terminal renderer, the OpenTelemetry attributes, the status dashboard, and the verification-group step-header naming raised in the issue's follow-up comment are all outside this slice; the follow-up comment's non-build-step visibility is a separate display concern that does not flow through this watcher, which is constructed only for the build step and stopped when that step's await settles.

This is an engine and daemon-log observability correction; acceptance criteria live in technical stories rather than a PRD.

The slice carries a factual activity timestamp rather than classifying the step as live or wedged inside the watcher (approved by the operator on 2026-09-06 for #2340 and reaffirmed on 2026-09-28, delegated). A timestamp needs no invented freshness threshold, keeps the judgement with the operator reading the line, and stays meaningful to every other consumer of the persisted event.

The issue's hypotheses were weighed. Provider process liveness was rejected: the watcher has no handle on the provider process, and the heartbeat module states that heartbeat presence is never process-liveness authority. Provider rollout-file mtime was rejected as a provider-private path with no engine-side contract. A dirty-worktree delta was rejected as a second git probe on the hot poll path for a signal the heartbeat already summarizes. Moving the quiet threshold was rejected: the second desired outcome requires a wedged step to warn at least as promptly as today, so this slice qualifies the warning rather than delaying it.

Scope check: A — consumer-facing (engine and daemon-CLI code that any repository running the daemon executes; no self-host, validation-gate, release-gate, or repository-private convention is touched), so no rules file changes and no catalog registration; B — n/a (no new skill); C — provider-agnostic (the heartbeat is written by the shared dispatch path for every provider, and nothing here reads a provider name).

Event spine: Channel? no — nothing new observes, reports, or coordinates; an existing watcher reads an existing file and enriches an existing event. Concern: occurrence, the quiet episode. Verdict: extend the union with one additive optional field on the existing quiet variant. Exception: none needed.

Verified foundation: `src/conductor/src/engine/build-progress-watcher.ts` emits `build_no_progress` from a single site in the unchanged-tick branch of `tick()`, guarded by `quietFired`, with `resolved`, `total`, `currentTaskId`, `lastCommitAt`, and `featureSlug` in hand, and its options carry `projectRoot` and an injectable `now`. `src/conductor/src/engine/step-heartbeat.ts` exports `readStepHeartbeat` (null for missing or malformed), `heartbeatBelongsToDispatch` (same step and stamped at or after the dispatch start), and `formatHeartbeatAge`. `src/conductor/src/engine/step-runners.ts` creates the pulse with `createHeartbeatPulse(this.projectDir, step)` in `dispatchProviderWithLifecycleSupervision`. `src/conductor/src/engine/conductor.ts` constructs the watcher only for the build step and starts it immediately before the step's await. `src/conductor/src/daemon-cli.ts` renders the `build_no_progress` case from `displayBuildPosition`, `formatCommitAge`, and the slug. `src/conductor/src/types/events.ts` declares the quiet variant with an optional `lastCommitAt`. The approved decision record `adr-2026-07-10-intra-step-build-progress-events` fixes the watcher lifecycle and quiet determination, neither of which changes; one more optional payload field is additive, so no decision record is created or amended.
