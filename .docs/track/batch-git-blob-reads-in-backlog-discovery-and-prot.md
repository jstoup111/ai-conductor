# Track: Batch git blob reads in backlog discovery and protected-artifact seal

Track: technical

Scope boundary: Small fix for #2065, approved by the operator on 2026-09-06 (delegated). Replace the one-subprocess-per-file read shape in daemon backlog discovery and in the protected-artifact reads taken at a commit with a single batched git read per pass. Scan results, seal fingerprints, and every existing refusal stay byte-identical. Cross-poll caching keyed by the discovery ref, a persistent long-lived reader process, the workspace-side protected-artifact reads, and the scoped reseal read are outside this slice.

This is internal engine performance work with no user-facing surface; acceptance criteria live in technical stories rather than a PRD.

Approach selection: the filer offered three hypotheses — a batched reader, a bounded-concurrency map over the existing per-file reads, and a cross-poll cache keyed by the discovery ref. A bounded-concurrency map was weighed and rejected: both discovery loops are serial `for await` loops, so a concurrency limiter alone changes nothing there without also restructuring the loops, and it still leaves cost scaling as one process spawn per artifact — which the desired outcome explicitly rules out. A cross-poll cache was weighed and rejected for this slice: it adds an invalidation contract (ref SHA, force-push, refresh semantics) that is a design decision the issue leaves open. A genuine alternative not derived from the filer's sketch — teaching discovery to read the working tree instead of the committed tree — was rejected because the committed-tree-only read is the deliberate "merged means build-ready" contract documented on the tree source. One batched read per pass wins: it collapses ~2,500 spawns to two, needs no new invalidation contract, and the same helper removes the seal path's unbounded fan-out.

Scope check: A — harness-repo-only (daemon discovery and self-host seal machinery, neither of which exists outside this repository); B — n/a (no new skill); C — provider-agnostic. No catalog registration is required.

Verified foundation: `gitTreeSource` in `src/conductor/src/engine/daemon-backlog.ts` implements `readFile` as one `git show <baseBranch>:<path>` per call (line 115); `discoverBacklog` constructs a fresh tree source per scan (line 714) and drives it through a serial approval loop over every decision record (line 834) and a serial per-plan loop reading plan, stories, tier marker, track marker, coherence, and intake (lines 852, 922, 915, 1141, 997, 1090). `src/conductor/src/engine/daemon.ts` calls `discoverBacklog` on every dispatch iteration (line 1303) and again when drained (line 1316) against `idlePollMs = 5000` (line 780). In `src/conductor/src/engine/protected-artifact-seal.ts`, `protectedArtifactsAtCommit` (line 566) and `createSeal` (line 707) each run an unbounded `Promise.all` of `contentAtCommit` (line 554, one `git show` per file) over every path `committedProtectedPaths` lists (line 542), and `protectedArtifactsAtCommit` is invoked for both HEAD and the base tip (lines 653, 657). Measured on this checkout: the committed spec corpus discovery reads is 2,485 files, and one `git ls-tree` piped into one `git cat-file --batch` returns all of them in 0.24s.
