# Track: Plan-growth budget resolves daemon feature plans

Track: technical

Scope boundary: Plan-growth accounting only (intake jstoup111/ai-conductor#2822, operator-preauthorized). Included: the authored-task derivation resolves the feature plan through the same identity ladder as `resolveRepairPlanBinding` (engine-recorded `activePlanPath`, then the singleton corpus, then the plan whose stem equals the conduct-state feature); one shared plan-growth budget computation (authored, added, cap, cap source, remaining) consumed by `ai-conductor daemon status`, `ai-conductor kickback-budget inspect`, the refusal-rework allowance check, build-boundary pending-repair settlement, and the remediation append budget; recorded remediation appends count as added, never as authored, in both the reported and the enforced numbers; a feature with no resolvable plan and no growth record is reported as unresolved rather than as a cap of 0. Excluded: changing the cap formula or config keys (`prd_audit.max_appended_tasks`, `prd_audit.max_appended_ratio`), the fail-closed enforcement for a genuinely unresolved plan, reclassifying `rem-*` headings that no growth record attributes (the legacy no-record rule stays), child-scoped (`--child`) inspect, recording `activePlanPath` at daemon dispatch, and any new event, sidecar, or CLI flag.

Internal operator tooling and engine accounting with no product requirements; acceptance criteria live in stories.

## Approach decision

- **Chosen — shared ladder + one budget computation (filer hypothesis, wins on merits).** `deriveGrowthFromActivePlan` (`src/conductor/src/engine/kickback-ledger.ts:885-918`) resolves the plan through `selectFeaturePlan` (`artifacts.ts:822-847`) with the conduct-state feature, exactly as `resolveRepairPlanBinding` (`repair-plan-binding.ts:29-41`) does. A single `readPlanGrowthBudget` in `remediation-caps.ts` replaces the four inline cap computations (`daemon-observe-cli.ts:595-602`, `kickback-budget-cli.ts:42-56`, `conductor.ts:6111-6113`, `conductor.ts:8911-8914`) and the raw heading count at `conductor.ts:4059`. Est. effort ~half day. Impact: the budget view cannot drift from enforcement again, and every `readGrowth` consumer (including refusal-rework admission) stops seeing authored 0 for daemon features.
- **Rejected — record `activePlanPath` when the daemon dispatches a spec-landed feature.** Not derived from the filer's sketch. Fixes new features only, leaves already-running worktrees wrong until their first remediation (which already records it since #2869, `conductor.ts:3575-3597`), and leaves four duplicated cap computations free to drift. Est. ~2h.
- **Rejected — views read the last cap the engine enforced (persisted at settlement).** No cap exists before the first remediation, which is exactly when operators misread the budget; adds a second source of truth beside the ledger. Est. ~half day.
