# Track: Bind story-N task references to Story N at land

Track: technical

Scope boundary: Small fix for #2174, approved by the operator on 2026-09-06 (delegated). Correct the plan `**Story:**` reference grammar so an optional `Story`/`Epic` prefix word is consumed together with the separator that follows it, route the three existing copies of that grammar through one shared parser, and name an unbindable reference in the orphan-task finding. Out of this slice: multi-id story lines (`**Story:** Story 1a + Story 2a` captures only the first id today and continues to), the stories-file heading grammar, the Coverage Check table row grammar, the orphan-task rule itself, and any skill-text or documentation change.

This is an engine parser correction with no product-visible requirement behind it, so acceptance criteria live in technical stories rather than a PRD.

The operator's alternatives were weighed on 2026-09-06 (delegated): (a) normalize the prefix inside one shared parser, (b) patch each of the three regexes in place, (c) reject the `story-N` spelling loudly at land instead of accepting it. (b) leaves three drifting copies of a grammar the repository already declares shared, and (c) spends an operator round on a spelling the issue calls natural. (a) was selected, with the loud-failure half of the desired outcome kept as the diagnostic for references that still bind to nothing.

Scope check: A — consumer-facing (the plan/stories land gate ships with the engine and runs in every repository that installs the harness), though the change lands no rule, documentation, or skill artifact, so no placement follows from that verdict; B — n/a (no new skill); C — provider-agnostic (pure text parsing, no host seam, no provider path or variable). No catalog registration is required. Event spine: no channel is added — the change alters the text of an existing land gap, not how it is carried.

Verified foundation: the identical value regex `/\*\*Story:\*\*\s*(?:story|epic)?\s*([A-Za-z0-9.\-]+)/gi` appears three times — `collectPlanCoverage` (`src/conductor/src/engine/artifacts.ts:5308`), `extractTaskStoryIds` (`src/conductor/src/engine/engineer/coherence-validator.ts:580`), and `extractCitedStoryIdsFromBlock` (`coherence-validator.ts:824`, differing only in using `[ \t]` for its separators). Story ids are produced by `splitStoryBlocks` (`src/conductor/src/engine/story-criteria.ts`) from `## Story <id>` headings, so `-3` matches nothing. `collectPlanCoverage` feeds the plan-coverage step gate (`artifacts.ts:4017`); `extractCitedStoryIdsFromBlock` feeds `checkOrphanTasks` (`coherence-validator.ts:857`), whose finding today carries only `task-<id>` and the task title. `src/conductor/src/engine/plan-task-parse.ts` declares itself "the stable home for the shared grammar/parser" and is already imported by both files, so it hosts the shared parser without a new module or a new import edge.
