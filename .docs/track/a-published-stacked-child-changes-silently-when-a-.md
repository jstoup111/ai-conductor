# Track: A published stacked child changes silently when a routed fix lands in it

Track: technical

Scope boundary: This is the first post-publication engine write path. Only routed work may pass the published-stack freeze: audit-routed rounds and `ai-conductor stack land` operator rounds. The engine keeps its replay restack, pushes the host and the restacked children above it at FINISH, after the re-pended leaf gates pass, and accepts a non-fast-forward only for a tip recorded by an applied restack whose remote still matches the pushed receipt. The host of a routed fix gets exactly one PR comment per fix, carrying the finding and the routing decision and listing the children above it that were only rebased. A child above it gets a comment only when its own diff changed, for example a resolved replay conflict. A child that was only rebased, a child whose tip did not move, an unpublished child, and a single-PR feature get no comment. Comments go through the guarded GitHub operation path and appear in the operation audit. A landing on a published stack reopens the finished feature so FINISH can run again, with the operator-confirmed reopen as part of this scope. Delivery is sliced, as the operator directed. Out of scope: other restack producers (feature-repair preflight, FINISH base refresh, sweep ci-fix) stay frozen, the closed-child rewind stays refused, and `stack adopt`, verified acceptance of a server-side rebase, and partial-merge recovery stay with #3268.

Engine write-path machinery with no product requirements of its own: acceptance criteria live in stories, matching every prior stacked-delivery spec.
