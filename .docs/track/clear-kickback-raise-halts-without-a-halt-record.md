# Track: Clear kickback raise halts without a halt record

Track: technical

Scope boundary: Small fix for #2752, approved by the operator on 2026-09-28 (delegated). A consumed kickback-budget raise must clear its halt when the feature branch has no committed halt record, keep resolving a record that exists in `halted` state, and keep the halt (with a logged reason) on any genuine record read or write failure other than absence. Changing which halt dispositions write a record, the authorization-selection logic in `consumeResumeAuthorizations` (tracked separately by #2595), the halt-record format, and the other halt-clear seams' best-effort handling are outside this slice.

This is internal daemon recovery machinery; acceptance criteria live in technical stories rather than a PRD.

Approach: treat an absent record file as nothing to supersede (`noop`) inside `supersedeHaltRecord`, and include the failure reason in the retention log line. The filer's alternative of making `kickback-cap` a recordable class was rejected: `adr-2026-08-29-kickback-budget-recovery-uses-needs-human-halt-class` keeps committed-halt recordability unchanged, and `adr-2026-08-23-committed-halt-record` decision 7 only rewrites a record that exists, so an absent record is an expected state, not a failure. No ADR is amended.

Scope check: A — harness-repo-only (the daemon kickback-budget resume path and committed halt records exist only in this repository's engine); B — n/a (no new skill); C — provider-agnostic. No catalog registration is required. Event-spine: no new event, metric, or channel; the change only adds the reason to an existing daemon log line.

Verified foundation: `src/conductor/src/engine/halt-record.ts` `supersedeHaltRecord` calls `readFile` on the record path and its outer catch returns `{ kind: 'failed' }` for every error including ENOENT; an already-resolved record returns `noop`. `isRecordableHaltClass` covers only `needs-human`, `plan-gap`, and `protected-artifact`, and `halt-classification.ts` maps the `prd_audit` and `architecture_review_as_built` caps to the `kickback-cap` disposition, so those halts never write a record. `src/conductor/src/engine/daemon-rekick.ts` `clearHaltForResume` returns `partial` and logs `halt record not superseded — halt retained` (no reason) when the resolver reports `failed`. `src/conductor/src/daemon-cli.ts` wires `resolveCommittedRecord` to `supersedeHaltRecord(worktreePath, feature, 'kickback-budget')`. The other callers (`daemon-deps.ts` `appendHaltClearedRecord`, `conductor.ts` stall path) ignore the result, so returning `noop` for absence does not change them.
