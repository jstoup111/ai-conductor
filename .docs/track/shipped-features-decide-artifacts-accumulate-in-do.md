# Track: Operator CLI prunes shipped features' DECIDE artifacts

Track: technical

Scope boundary: Comprehensive within an operator-run CLI (operator-confirmed 2026-10-15). In scope: (1) a new `ai-conductor docs-prune` command that removes the prunable DECIDE artifacts of every stem whose shipped record is on `origin/main`, through one guarded, reviewable docs-only PR (never a direct push, never a merge); (2) one shared retention policy; (3) deferral of any path an open PR modifies, with every removed and deferred path reported in the PR body and on the event spine; (4) shipped-record repair and the shipment audit keep working for pruned stems by reading the plan from the last commit that carried it, or fail with a specific, actionable refusal. Retention: keep `.docs/stories`, `.docs/specs`, `.docs/decisions` (incl. superseded ADRs), `.docs/architecture`, `.docs/shipped`, `.docs/intake`, `.docs/release-waivers`; prune `.docs/plans`, `.docs/conflicts`, `.docs/coherence`, `.docs/coherence-waivers`, `.docs/track`, `.docs/complexity`, `.docs/halted`, `.docs/plan-review`, `.docs/applicability`, `.docs/retros` for shipped stems. Exclusions: no finish-time pruning, no daemon sweep, no automatic trigger; no `spec_hash`, shipment-evidence or seal contract change; repository-wide `.docs` files (`audit`, `audits`, `baselines`, `observation`, top-level files) are untouched; #1676 is not re-fixed (absorbed by #1752, shipped in PR #3041).

Internal harness tooling with no product requirements; acceptance criteria live in stories. Not a maintenance change class (adds behavior), so no applicability marker. Source: jstoup111/ai-conductor#2963.
