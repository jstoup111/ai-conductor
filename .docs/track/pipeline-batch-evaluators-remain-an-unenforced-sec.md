# Track: Pipeline batch evaluators remain an unenforced second review authority

Track: technical

Change class: none (not maintenance: the spec adds the tail's `unadmitted-type` diagnostic and flips the security default, so acceptance specs apply)

Scope boundary: Comprehensive (operator-selected scope C), widened twice by the operator during DECIDE. (1) Retire the `/pipeline` batch-boundary evaluator dispatch, its tier table, its hard gate, and its `review.json` / `code-review-satisfied.md` audit-trail requirements. (2) Remove every harness doc, skill, agent, and template claim that a batch evaluator runs or satisfies the code-review gate. `build_review` becomes the single documented post-build review authority. (3) Make the build_review `security` rubric enabled by default (an absent `rubrics.security` block resolves to enabled; `enabled: false` opts out), because the batch evaluator's security check was the only default security review. (4) Retire the whole pipeline closeout-obligation telemetry channel, which has no producer once the evaluator is gone, per adr-2026-10-12-retire-pipeline-closeout-obligation-telemetry. That covers: the `pipeline_closeout*` event kinds, the `ai-conductor closeout-event` subcommand, `closeout-trust.ts`, the closeout OTel histogram and span event, the renderer and daemon-log closeout lines, and the build-tail rollup's closeout segment. Alongside the retirement, the sibling-ledger tail admits only declared external kinds. Approach 1 was selected for the evaluator itself: retirement with no new contract guard and no dedicated retired-command refusal. Preserved: per-batch-boundary `/simplify`, lint, and affected-test runs; the orphaned-caller grep gate; the standalone `/code-review` skill and the `agents/evaluator.md` persona it dispatches; the `evaluator` model-table row, re-scoped to `/code-review`; and the `.pipeline/pipeline-events.jsonl` sibling ledger and its tail for build-review and kickback-budget events. Accepted by the operator: a build still running old `/pipeline` text may block once after an engine rebuild and recover through re-dispatch, with no transitional tolerance and no runbook note. Excluded: any new evaluator-like gate, an advisory evaluator, any other `build_review` rubric change (security's effort default, vocabulary, and stacked grading, plus `testQuality`'s default-off), and renaming the closeout-named ledger modules.

Internal harness tooling with no user-facing product requirements; acceptance criteria live in stories.
