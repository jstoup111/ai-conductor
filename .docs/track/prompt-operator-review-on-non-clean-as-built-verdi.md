# Track: Prompt operator review on non-clean as-built verdicts

Track: technical

Scope boundary: Small fix for #2698. Decision OD-4, left open by the as-built typed-verdict feature, is resolved: approved by the operator on 2026-09-28 (option A). In a non-auto run with the as-built step's review mode `conditional`, the engine derives the review-required signal from the typed as-built verdict instead of a reviewer-written marker file. A non-clean verdict that completes the step prompts the operator; a clean `APPROVED` verdict does not. Auto/daemon mode is unchanged. Marker-file behavior for every other conditional step, the as-built verdict contract, remediation routing, and halt semantics are outside this slice.

This is an internal engine correction; acceptance criteria live in technical stories rather than a PRD.

Scope check: A — harness-repo-only in mechanism terms (the conductor artifact review gate and typed as-built verdict store exist only in this engine); consumer projects observe it only as the interactive review prompt. B — n/a (no new skill). C — provider-agnostic (the decision reads the persisted typed verdict, not provider output). No catalog registration is required. Event-spine: no new event, metric, log line, or channel; the existing `onReviewArtifacts` callback is the only observable.

Verified foundation: `src/conductor/src/engine/conductor.ts` runs its artifact review gate only when `this.mode !== 'auto'` (line 13543) and, for `conditional` review, prompts only when `.pipeline/review-required-<step>` exists; nothing writes `review-required-architecture_review_as_built`, and `as-built-typed-verdict-audit-gaps.acceptance.test.ts` (S6.6) currently pins the never-prompts behavior. `resolved-config.ts` sets `architecture_review_as_built: 'conditional'`. The built-in validation group engages only when `this.mode === 'auto'` (line 8021), so in non-auto runs the as-built step dispatches serially and reaches the success-path review gate only when its completion predicate returns done. Reachability finding: the `architecture_review_as_built` predicate in `artifacts.ts` (line 3425) returns done only for `asBuiltOutcome` `approved` (verdict `APPROVED` or `APPROVED WITH DRIFT NOTES`) and `plan-gap-delivered` (`PLAN_GAP` with `outcomeDelivered: true`). `BLOCKED` and undelivered `PLAN_GAP` return not-done and route to remediation or a halt before the success path, so they never reach the gate. The stories are therefore scoped to the two non-clean verdicts that can reach it: `APPROVED WITH DRIFT NOTES` and delivered `PLAN_GAP`. `readAsBuiltVerdict` in `as-built-verdict-store.ts` is the sole typed-verdict reader and returns `absent`, `unreadable`, or `present`.
