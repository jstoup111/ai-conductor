# Track: Record task done completion without a current-task stamp

Track: technical

Scope boundary: Small fix for #2809 (carved out of #1252 outcome 3), approved by the operator on 2026-09-28 (delegated). When `conduct task done <id>` finds no current-task stamp and the task has no open repair, it applies the same engine-owned Done when close contract the stamped path applies: it records the evidence and marks the row completed, or refuses naming the missing check. An already-completed or skipped row still closes idempotently with exit 0, a different task's stamp is still never cleared, and the plan-gap request is honored without a stamp. Legacy tasks with no Done when block keep their prior close rule unchanged. The stamp writers (session hook, `task start`), repair-obligation semantics, trailer resolution, and the rest of #1252 are outside this slice.

Approach decision: record completion rather than refuse. The approved ADRs settle the fork. adr-2026-07-26-concurrent-task-telemetry-and-symmetric-self-host-isolation decision 1 makes `.pipeline/current-task` non-authoritative telemetry that "cannot block mutation, completion, or acceptance"; refusing a close because the stamp is absent would make it block completion. adr-2026-08-22-done-when-evidence-at-task-close decision 1 makes the proof boundary the per-check Done when evidence the engine records before marking a task completed, with no stamp precondition, and decision 2 keeps tasks without the block on the prior rule. The existing reopened-task branch already records stampless completion through the same writer. Refusing was the filer's hypothesis only.

This is internal engine and orchestration-contract behavior; acceptance criteria live in technical stories rather than a PRD.

Scope check: A — consumer-facing (the `conduct task done` engine command and the shipped `skills/pipeline` contract text exist in every consumer project); B — n/a (no new skill); C — provider-agnostic (it removes a host-specific trap for hosts without a session hook). No catalog registration is required. Event-spine: no new event, metric, log channel, or report; existing stderr refusals are reused.

Verified foundation: `src/conductor/src/engine/task-cli.ts` runTaskDone reads the stamp and, when the read fails, calls openRepairForTask and returns 0 at line 259 for `repair.kind === 'none'` without writing anything; only an open repair reaches completeTaskDoneWhen. The stamped path (line 269 onward) refuses a different stamp, routes `--plan-gap` to runTaskPlanGap, then calls completeTaskDoneWhen. `src/conductor/src/engine/task-progress.ts` completeTaskDoneWhen (line 284) resolves the plan from engine state or the feature-slug binding, returns legacy at lines 309 and 332 when no plan or no Done when block exists, refuses missing evidence, and is the sole writer of `completed` plus `doneWhen` records. It does not short-circuit an already-completed row. `skills/pipeline/SKILL.md` lines 70, 96, and 132 and `docs/reference/cli.md` line 738 document the stampless no-op.
