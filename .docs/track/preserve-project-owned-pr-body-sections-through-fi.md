# Track: Preserve project-owned PR body sections through finish

Track: technical

Scope boundary: Balanced fix for #2616, confirmed by the operator on 2026-09-24. A project declares the pull request body regions its custom steps own in its own pull request template, not in `.ai-conductor/config.yml`: each region is wrapped in HTML comment markers that name a custom step key (`<!-- ai-conductor:step <key> -->` … `<!-- /ai-conductor:step -->`), and a marker naming a built-in step or an undeclared step is rejected. The SHIP draft pull request body is seeded from the project's pull request template when one exists, so the marked regions exist before the step runs; without a template, today's hard-coded draft body is unchanged. When the owning step reports success, the engine captures its region's bytes; a missing or empty region halts the run naming the step. After every finish body rewrite — prose authoring, the prose judge's repair, and the halt-PR body floor — the engine re-inserts every captured region byte-for-byte and verifies them before the pull request is marked ready. This repository's `release-disposition` step moves onto the mechanism, and the engine's `Release-*`-specific snapshot and restore is deleted. In scope: the SHIP draft seed, floor and halt-PR recognition of a template-seeded draft, the shipped `pr` and `finish` skills' body guidance, the repo-local `release-disposition` skill, and this repository's pull request template. Out of scope: the finish prose author following the project template's other headings (the rest of #826), engine-owned section mechanics (reduced build-review coverage, accepted risk, the plan declaration line, the closing reference), the spec-PR release disposition injection, and the release workflows' parsers beyond tolerating the region markers.

Custom steps contributing to the pull request body is internal harness machinery with no end-user product surface; acceptance criteria live in technical stories rather than a PRD.

The operator chose template-declared regions over a `pr_body_contribution` config key (consistent with how GitHub itself treats pull request templates), chose markers tied to a declared custom step key over free-form labels (so a missing contribution names its step and engine sections cannot be claimed), and chose to seed the draft from the template.

Scope check: A — mixed, split by surface: the finish region preservation, the template-seeded draft, and the shipped `pr`/`finish` skill guidance are consumer-facing (finish runs for every repository, and any consumer can declare custom steps and a pull request template); the `release-disposition` migration, this repository's `.github/pull_request_template.md`, and deletion of the self-host `Release-*` snapshot/restore are harness-repo-only. B — n/a (no new skill). C — provider-agnostic (HTML comment markers and pull request body edits carry no host-specific path, variable, or capability; the shipped skill edits apply to every host).
