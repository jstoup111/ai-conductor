# Track: BUILD-origin plan-gap recovery refuses rewind to BUILD

Track: technical

Scope boundary: Narrow (composer-run, operator pre-authorized 2026-10-09). In scope: (1) when `ai-conductor rewind --to <step>` (whole-feature, no `--child`) is refused because `<step>` is the halted feature's own recorded `last_step` and that step's status is `refused` or `failed`, the refusal keeps its existing message and state-preserving behavior but also names the supported in-place recovery, `ai-conductor halt clear --feature <slug> --rationale "<what you fixed>"`; (2) the shipped `daemon-triage` skill's plan-gap routing distinguishes a plan gap raised inside BUILD (`last_step` is `build`; recover in place with `halt clear` after amend + reseal) from one raised by a later SHIP validator (`rewind --to build`). Excluded: loosening `rewind`'s strictly-earlier guard (accepted Story 4 of `.docs/stories/needs-human-halt-auto-resumed-at-dispatch-rewind-c.md` keeps it); any change to `halt clear`, park/unpark, resume selection, or `task done --plan-gap`; the `--child` rewind path. Reader-facing runbook/CLI reference reconciliation is owned by the documentation step, not this spec's tasks.

Operator CLI diagnostics plus agent-instruction routing — no product requirements; acceptance criteria live in stories. Root cause (verified): `ai-conductor task done <id> --plan-gap` raises the plan-gap HALT from inside BUILD, so `recordStepRefusal` leaves `last_step: build`, `build: refused` (`src/conductor/src/engine/conductor.ts:732-741`), and `rewindState` refuses any target not strictly earlier than `last_step` (`src/conductor/src/engine/rewind.ts:343-348`). The runbook's plan-gap procedure (`docs/runbooks/stalled-or-stuck-feature.md:909-935`) and the `daemon-triage` table row (`skills/daemon-triage/SKILL.md:173`) only anticipate prd_audit/as-built origins and prescribe `rewind --to build`. The shipped, supported recovery for an in-place halt is `ai-conductor halt clear` (#2132): it clears HALT/HALT.class with an audited `halt_clear_authorized` event, leaves `conduct-state.json` untouched, never touches the park marker (`src/conductor/src/engine/halt-clear-cli.ts`), and resume re-enters the refused step because `findResumeIndex` starts after the last `done` step (`src/conductor/src/engine/resume-entry.ts:121-146`) and a `refused` step is not gate-satisfied (`src/conductor/src/engine/selector.ts:46-58`); implementation commits, task-status rows, and unfinished edits are not touched by either command. Chosen approach A (route BUILD-origin plan gaps to the existing in-place `halt clear` recovery; make the rewind refusal name it) over B (filer-adjacent: let `rewind` accept the current step when it is `refused` — contradicts the accepted strictly-earlier contract and duplicates `halt clear`, since there is nothing downstream of a first-lap refused BUILD to invalidate) and C (make the BUILD plan-gap report record `last_step` as BUILD's predecessor — falsifies the state that drives halt attribution, triage, and resume).
