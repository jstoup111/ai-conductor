# Track: Audited operator halt clear for in-place halts

Track: technical

Scope boundary: Balanced (operator-confirmed 2026-10-02; documentation reconciliation removed 2026-10-03). In scope: (1) an audited operator CLI verb (`ai-conductor halt clear --feature <slug> --rationale "<why>"`) that clears a live HALT + HALT.class for any halt class, appends an operator-attributed `halt_clear_authorized` event carrying the rationale, and supersedes the committed halt record, so the daemon resumes at the recorded `last_step` through its existing HALT-absent path — including when `last_step` equals the halted step; (2) the build-stall remediation path preserves the remediation outcome's halt class (e.g. `kickback-cap`) instead of always writing `needs-human` via `writeStallHalt`; (3) the build-stall path's clear of the agent-written halt marker no longer records `cause: 'operator'`. Excluded: documentation reconciliation of `docs/reference/cli.md`, `docs/runbooks/stalled-or-stuck-feature.md`, and `CLAUDE.md` (operator-confirmed: out of scope, no follow-up); an engine-level guard refusing dispatch over an inherited live HALT; `lastResolvedCount` stamping on stall-halt exits; any change to `rewind`'s strictly-earlier guard (unchanged for all cases).

Operator CLI and engine halt bookkeeping — no product requirements; acceptance criteria live in stories. Daemon auto-resume of needs-human halts is already fixed (#2206/#2398); the remaining gap is the missing audited recovery path. Chosen approach B (dedicated verb) over A (`rewind --allow-current`: rewind's job is downstream invalidation, nothing to invalidate here, and the build-stall halt is raised inside `build` so `last_step` is always `build`) and C (widen per-class verbs: leaves needs-human halts without a reseal uncovered and keeps the `rm -f` docs).
