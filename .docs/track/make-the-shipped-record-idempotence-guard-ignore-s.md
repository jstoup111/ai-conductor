# Track: Shipped-record idempotence over non-telemetry substance

Track: technical

Scope boundary: Small fix for #1648, approved by the operator on 2026-09-06 (delegated). Decide whether to commit a re-rendered shipped record by comparing its non-telemetry substance against the record already committed at HEAD, and keep the committed bytes on disk and in the index when only the self-updating rollups moved. The rollup computation itself, the event schema behind it, the KPI reader, the post-finish refresh caller, and the sibling existence-check defect in the finish publication adapter are outside this slice.

This is an internal engine correction to a git-commit decision; acceptance criteria live in technical stories rather than a PRD.

The operator approved comparison over freezing on 2026-09-06 (delegated). Two approaches were weighed. Approach A excludes the self-updating rollup blocks from the idempotence comparison and preserves the committed bytes when nothing else changed; it is two production files and leaves the rollup contract untouched. Approach B freezes the rollup at a defined boundary by excluding the writing dispatch from the aggregation, which requires the writer to know its own dispatch identity and threads through the cost rollup, the event payloads, and the coordinator — larger than this tier and a change to the approved per-feature cost-rollup contract. Approach A was recommended and taken. The filer's first hypothesis is Approach A; the genuine alternative weighed against it is Approach B.

Accepted consequence, recorded on 2026-09-06 (delegated): once the guard fires, the committed record keeps the telemetry captured at its first write on the branch, so no committed value is any longer a function of a later write of the same record. The finish tail that runs after that first write is no longer folded into the committed Cost block. The build itself dominates the per-feature total, so the tokens-per-shipped-feature KPI keeps its meaning, and this is the tradeoff the intake anticipated when it observed that the second writer exists only to refresh that block.

Scope check: A — harness-repo-only (the shipped-record ledger and its dedup are conventions of this repository's own construction); B — n/a (no new skill); C — provider-agnostic (no provider names, models, or host-specific behavior). No catalog registration is required. No behavioral rule is added, so neither the shared rules file nor the repo-local one changes; the reader-visible CLI reference sentence that states the current comparison is updated in the same diff.

Verified foundation: shipped-record-cli.ts renders the record, then unconditionally stages it and commits when `git diff --cached --quiet` reports a staged change, so a body whose rollups move on every write can never take the already-committed branch. shipped-record.ts renders the Cost block from a CostRollup whose `dispatches` counter increments per dispatch event, and appends a Time block whose active milliseconds grow with every dispatch; both are read from the feature worktree's own event ledger. conductor.ts refuses to enter its post-finish refresh transaction unless `git diff --quiet` and `git diff --cached --quiet` both pass, so any guard that leaves the record staged would break that caller, and it already returns early when the refresh produced no new commit. The approved per-feature cost-rollup decision fixes the Cost block's contents and its home, not the commit decision, so no decision record is amended.
