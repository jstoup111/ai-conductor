# Track: Manual-test report left in product worktree blocks next routed host

Track: technical

Scope boundary: Small. Covers the three SHIP-tail validation gates (manual_test, prd_audit, architecture_review_as_built) on both the grouped and serial dispatch paths. Untracked files a validation dispatch creates are moved into `.pipeline/` before the engine routes the outcome. Tracked modifications, staged changes, and untracked files that existed before the dispatch are never moved and still block routed host entry. The manual-test skill names a harness-owned evidence directory under `.pipeline/`. Out of scope: build_review and other steps; validators committing product code (#3685); the routed-host-entry dirty check itself, which stays fail-closed.

Engine bug fix in the daemon's SHIP-tail validation flow. It has no user-facing product requirements, so the acceptance criteria live in stories. Chosen approach: quarantine new untracked validator output at the end of the validator dispatch. This is the point where the violation happens, and it follows the rebase untracked-quarantine precedent in `src/conductor/src/engine/rebase.ts`. The skill also names an evidence location. Rejected alternatives: a skill-only instruction (an agent can still drift, and a stray file would still halt); relaxing the dirty check at routed host entry (it cannot tell stray output from real uncommitted work, and it would also hide residue left by build); failing the manual_test gate on a dirty tree (a FAIL attempt is routed whatever the gate verdict, which is exactly what happened in the incident, and each retry costs another agent attempt). Operator delegated approach and track acceptance to the composer agent on 2026-11-15.
