# Track: ADRs carry a machine-checked assumption ledger

Track: technical

Scope boundary: Balanced (operator-selected), narrowed during architecture review by operator decision on 2026-10-10. Every ADR a spec newly adds carries a structured `## Assumptions` section: either the explicit statement `No load-bearing assumptions.` or a ledger table whose entries each state the assumption, basis (verified / inferred / unverified), confidence %, whether it is load-bearing, and impact if wrong. Every load-bearing entry whose basis is not `verified` (inferred OR unverified) carries a per-entry operator approval marker recorded in the ADR. A pre-existing ADR the spec changes is checked only if it already carries the section. One shared parser enforces presence and shape at two points: the `ai-conductor compose land` gate, next to the existing approval, citability and filename rungs, and the `/conduct`-path `architecture_review` gate. That step's enforcement moves from `advisory` to `gating` so a failure actually blocks. The ADR template and the architecture-review / verify-claims skills are updated to author the section. Excluded: a daemon-discovery rung, dropped by operator decision to follow the land-only precedent of adr-2026-09-02-adr-decision-citability-contract D4; retrofitting the existing ADR corpus (legacy ADRs are exempt); ledgers for PRD/stories/plan-level assumptions; any as-built-review spot-check of ledger entries against reality; LLM judgement of whether an assumption is really load-bearing. Shape is checked mechanically; the classification stays with the author and operator.

Internal gate machinery plus an artifact-format contract with no product-facing capability; acceptance criteria live directly in stories (intake jstoup111/ai-conductor#542).
