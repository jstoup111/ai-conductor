## Judgement notes

**outcome-4.** The staged bullet asks that adding a custom step be documented end to end and that
following that documentation not meet an engine-side special case for a name or path. The second
half is a behavior and is delivered by Story 1 (no reserved step name at FINISH) and Story 4 (the
configured skill, not the step key, is dispatched). Authoring the documentation itself is excluded
from stories and plan tasks by the documentation boundary and is delivered during BUILD by this
repository's documentation gate. The row is judged covered on the behavior, and this reading is
flagged for the operator in the specification pull request.

**Consistency pass.** Every covered row was re-read against its counterpart in both directions. The
one contradiction found in DECIDE — a drafted exemption for a skipped gating step against the shipped
rule that gating custom steps can never be skipped — was resolved before this artifact was written;
decision 6 of the amended ADR, Story 2, and Task 4 now agree that any status other than `done` is
missing. No cross-layer pair oscillates: satisfying Story 1 leaves Story 2 true because the selector
partitions steps into required and not required, and satisfying Story 5 leaves Story 1 true because a
consumer's step named `release-disposition` is an ordinary gating custom step outside a self-build.

**Preserved-behavior sweep.** Four criteria promise unchanged behavior. No-custom-steps repositories:
Task 3 bounds the new observer to zero filesystem calls when the selection is empty. This
repository's two dispatch prompts: Task 9 pins them to recorded strings. Built-in steps with a skill
override: Task 9 leaves registry-rendered steps untouched and asserts it. The consumer pull request
template and the hand-off injection: no task touches either path, and Task 17 observes both.

**Achievability.** Observer-level checks return `present`, `missing`, `stale`, `malformed`, or
`unavailable`; the criteria speak of valid, missing, invalid, and indeterminate release readiness.
The mapping between them is existing coordinator behavior, verified in source, and is a closed set
that represents every required scenario, including the no-prerequisite case. Task 2 carries the
step keys across that mapping and Task 7 proves the path end to end through the production
coordinator, so no criterion rests on an unstated connection between tasks.
