## Achievability notes

- **Region entry (Stories 1, 3, 4).** Every criterion is delivered through a named mechanism: `admitQueuedRevalidation`, `enterRoutedHostRegion`, `recordRoundStall`, `consumeLowestQueued`'s `busy` result, or `routingEligible`. Each is asserted at the criterion's layer, either the HALT file and class or the refs under `refs/conductor/<slug>/`. No check depends on Steps prose.
- **Representable outcomes.** The helper's closed result set (`continue`, `admitted`, `none`, `busy`, `stalled`, `unavailable`) expresses every scenario the stories require. `continue` carries `navigate-host` (entered), and `resume-exit` and `navigate-leaf-to-build` (mechanical HALT). `busy` covers both the fence refusal and the marker race. `none` covers the empty queue, and `unavailable` covers unreadable refs. Routing ineligibility is decided before the helper is called, so it needs no extra value.
- **ADR constraint sweep.** No criterion requires violating `adr-2026-10-12-routed-whole-feature-repair`. D7's "the append happens solely at region entry" is preserved because admission only creates the round and marker. #3445's fence and bounded stop (D7 amendment) are reused, not bypassed. D14's acknowledgement and production are untouched.
- **Input boundary.** Task 6's refusal reason reads the queued child and generation from the cursor's `revalidating` field. It reads the non-closed rounds from `diagnoseAffectedRounds`, the same source the #3445 stall HALT uses, so the rendered state comes from the durable refs rather than a prepared subset.
