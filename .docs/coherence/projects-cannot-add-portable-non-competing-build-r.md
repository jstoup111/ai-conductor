## Cross-layer consistency and preserved behavior

The following comparisons were checked in both directions against the actual criteria and completion blocks; each is resolved by a scoped mechanism rather than by assuming a descriptive label grants authority.

- **Disabled/default membership versus new discovery and telemetry:** Tasks 1/2 exclude disabled declarations and a disabled public gate before discovery/cache/judge calls; Tasks 12/14/20/33 preserve no-custom behavior. Task 40 describes emitted policy occurrences and their existing consumers, not an unconditional discovery or model event. The cache correction remains intentionally applicable to built-ins.
- **Package completeness versus usable installed selection:** Tasks 3–11 and 16 accept unique local project/global/plugin installations without modifying them, capture the whole admitted package, and deliver its exact material. Catalog errors, resource limits, and incompatibility settle as coverage failure. FR-3's amendment admits runtime-discovered unsupported results; no task claims arbitrary prose compatibility can be decided before invocation.
- **Stable review input versus provider bookkeeping:** Tasks 12–16 make source/material read-only and private scratch writable through both actual invoke adapters. Failed protected/scratch/nested probes stop before review. Task 26's coverage decision changes failure evaluation only and cannot supply a missing access capability or suppress a judged finding.
- **Fallback versus content-grounded reuse:** Tasks 15–20 prepare each actual candidate before policy resolution and lookup. Only existing provider/model-unavailability classification permits fallback; catalog/load/auth/cancel/malformed outcomes do not borrow another policy or an unauthorized route. Exact equivalent semantics hit; incidental runtime paths/timing/commit addresses do not become identity.
- **Complete sources versus suppression and settled recurrence:** Tasks 21–24/28–30/34 retain raw and historic evidence while deriving the eligible source set through validated confidence, current membership, exact operator decisions, and finalized non-action recurrence. Suppressed entries remain separate non-blocking history; source completeness applies to the actual eligible set rather than demanding dispositions for intentionally excluded history.
- **One aggregate authority versus no-content routes:** Tasks 32/33 own shared application/navigation; Tasks 24/34 own no-judge settled/infrastructure routes.
