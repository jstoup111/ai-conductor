## Consistency and achievability notes

- **Outcome wording.** Outcome 1 describes the halt as firing "before appending fix tasks", which is the pre-change behavior. Under the approved design the repair is appended before the cap halts, which is what lets the raise build it directly. This is the operator-directed mechanism, not a contradiction.
- **Preserved behavior.** Story 5's unchanged-halt criteria share a path with Task 5, which removes the cap exits, and Task 6, which adds a build-boundary side effect. Task 6 settles only when a pending record exists, and Task 11 asserts that build_review, test_suite and manual_test kickbacks settle nothing, so the preserved scenarios are excluded from the new effect.
- **Criterion judgement.** Every criterion row is identical to a plan Coverage Check row that passed the independent coverage judgement (two rounds, 2026-09-29), so no second judgement was run.
