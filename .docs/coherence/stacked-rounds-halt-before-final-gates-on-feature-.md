## Semantic judgement

All sixteen exact criteria were independently judged against the complete cited Done-when checks: 16 asserts, 0 refusals. That coverage result is corroboration, not a substitute for this achievability pass.

- Story 1 reaches the actual live dispatch boundary through Task 1's leaf-overlay restoration and Task 3's pending-validation selection. Task 4 retains routing precedence. The checks require real Conductor.run observations, not helper-only results; successful former-host evidence cannot stand in for the leaf.
- Story 2 reaches the actual restart boundary through Task 2 before entry derivation and the existing prerequisite clamp. Task 4 preserves current round ownership despite old return history; Task 5 observes refusal from unresolved identity or unreadable source state before dispatch. No prepared-success input can bypass those source failures.
- Story 3 dispatches the existing leaf suite/review owner through Task 3, with explicit no-BUILD and no-false-HALT assertions. Tasks 6 and 7 require old success to lose to stale/negative/missing authoritative evidence and preserve real validation failure. These legal outcomes use existing selection, invalidation and refusal behavior, not a new boolean aggregate.
- Story 4 is carried by Task 1's observable root/child persistence assertions, Task 2's flat-path regression and Task 6's missing-child rejection. The design's routed store can represent separate root and child cursors and compare-and-swap expectations; the checks require preservation, not unconditional success on genuine concurrent writes.

The conditional second intake outcome is covered by running genuinely required validation at its existing owner. The approved architecture has no mandatory additional root suite for a settled stacked round; this change does not invent one. The third outcome is scoped by the accepted stories to authoritative completed BUILD, avoiding a new task-counter bypass for unresolved obligations.

All four outcomes, four stories, seven tasks, and sixteen criteria have real counterparts. Each required Then outcome appears in a cited task check, with explicit failure/no-op outcomes. Every check names the production transition or observable dispatch/persistence boundary that delivers it. No approved structural constraint prevents these outcomes. No outside-diff dependency or waiver is needed: the assertions use bounded local fixtures and replaced third-party boundaries, not the live state of sibling features.
