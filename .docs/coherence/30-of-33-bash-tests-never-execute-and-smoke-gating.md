Consistency (§4d) was judged by a fresh subagent over the final stories and every plan task verbatim, under plan §7b. It found no conflict, and the plan has not changed since. The closest calls it examined are all orderings, not contradictions:
- The real manifest has no `shell-runner` entries until Tasks 8–13, and Task 14 is the first task to run the default manifest.

- Children of deleted runners must each carry their own entry or triage line.

Task-vs-task (§4d): Tasks 8–13 share `test/shell_tests.manifest`. They are serialized by dependency, and each task's `Done when` constrains only its own listed scripts. Task 14's whole-tree checks (full classification count, default runner exits 0) hold only after all six batches, and Task 14 depends on Task 13. Task 11 may delete `test_helpers.sh` only when no remaining script sources it. Every task from 8 to 13 requires each script that referenced a deleted script to still pass, so Task 10's possibly-kept `test_rtk_hook_reinit.sh`, which sources it, cannot be broken by Task 11.

Preserved behavior: Task 7 replaces `runSmoke`'s inline parse with `parseSmokeCapabilityDeclarations`, keeping the same messages. The existing "rejects a discovered smoke file with no declaration before running an executor" test is part of Task 7's same-parser check.

Achievability (§4g): each criterion row names the mechanism that delivers it and its observable assertion:
- `test/check_shell_test_classification.sh` and its fixed output prefixes;
- `test/run_shell_tests.sh` with its sandbox, `env -u` list, `timeout` and exit accounting;
- the `ci.yml` `shell-tests` job and `ci-gate` loop, through the YAML contract test;
- `parseSmokeCapabilityDeclarations` over `discoverSmokeFiles`;
- per-batch triage records checked by `run_shell_tests.sh` and `git grep`.
