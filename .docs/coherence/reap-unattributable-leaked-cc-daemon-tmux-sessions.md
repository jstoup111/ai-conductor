# Coherence: Dispatch process-tree teardown and leak status surface

Source-Ref: jstoup111/ai-conductor#544. Tier M, technical track, so there is no PRD and no `fr` rows. The staged intake outcomes file (`.pipeline/intake-outcomes.md`) carries no Desired-outcome bullets, so the `outcome` row class is not required and is omitted.

Scope note: the operator confirmed a Balanced scope for #544 (`.docs/track/reap-unattributable-leaked-cc-daemon-tmux-sessions.md`). The issue's test-side socket isolation outcome is delivered by #2476 (in flight) and #257 (shipped) and is excluded here. Its janitor outcome is narrowed to prevention at the source plus a read-only status surface, with no autonomous reaping.

Consistency pass: no cross-layer contradiction was found. An independent fresh-context contradiction judge ran over the final plan, stories and ADR decisions D1–D9 and returned no conflicts (see the sweep note below the criterion table). Task-versus-task pairs that share files were checked in both directions:
- Tasks 12, 13, 14 and 15 all edit `daemon-cli.ts`. Each adds its own exit-path ordering, and Task 12's uninstall is ordered after Task 14's completion teardown.
- Tasks 9, 10 and 11 touch separate adapters.
- Tasks 3 and 4 extend one module additively.
- Tasks 17 and 18 split computation from rendering.

None of these pairs invalidates another's Done-when.

Preserved behaviour:
- **Interactive (non-daemon) runs.** The registry is inert until the daemon installs it (Task 8), so these runs gain no signal or event.
- **SIGHUP and SIGTERM paths with nothing registered.** These send no signal, perform no sleep, and keep their fake-clock duration unchanged (Tasks 13 and 14).
- **`onSpawn`.** It keeps its observation-only contract (Tasks 9–11 leave it unchanged).
