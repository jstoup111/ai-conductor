# Coherence: Vitest daemon fixtures leak into shared operational OTel metrics (#2471)

**Date:** 2026-10-03
**Tier:** M
**Track:** technical. The `fr` row class is omitted because there is no PRD; the stories carry the requirement layer.
**Outcome source:** jstoup111/ai-conductor#2471. Outcome rows quote the staged sanitized bullets verbatim.

The current spec change set contains no `.docs/decisions/adr-*.md` file (the architecture review reuses ADR-014 unchanged), so the `adr` row class is omitted. Story and task rows are derived from the plan's `**Story:**` lines. Criterion rows are generated from the same source as the plan's Coverage Check, which passed independent coverage judgement on every row (round 1: 19 of 25; round 2: the 6 revised rows). The consistency pass (§4d) found no contradiction: the only new side effect on the production path is the refusal `renderer_error`, which fires only when `AI_CONDUCTOR_NO_REAL_EXEC` equals `1`, a value no production code sets, so Story 2's unchanged-production promise holds. Task 2 deletes the marker inside one case to prove Story 1's marker-deleted path; Story 4's Done When forbids that only for the transport and loopback export tests (Tasks 5 and 10), so the two do not oppose. Achievability (§4g): each criterion row names the mechanism that delivers it (`userConfigPath`, `test/setup.ts`, `otlpExportRefusal`, `buildExporters`, the three wiring entry points, the guard scanner) and its observable assertion.
