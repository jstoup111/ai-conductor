## Architecture decision review

D1: Tasks 2–3 require exclusive immutable election, multiple-dead-claim recovery, and a single active handle. Their checks preserve a live winner rather than deleting or replacing its authority.

D2: Task 1 requires owner/predecessor-derived slots with complete identity validation; Task 4 requires generation revalidation and forbids old authority over a replacement. Together they establish both the stored representation and its acquisition enforcement.

D3: Task 2 requires legacy root compatibility through actual acquire/release and the production filesystem, while Tasks 4–5 distinguish explicitly foreign binding from unbound legacy authority. Task 2's refused-store-write check includes live claimants. These checks preserve conservative older-client contention without requiring legacy metadata migration.

D4: Task 3 elects a single live winner; Task 4 checks authority before quarantine and abandons changed ownership; Task 10 confirms quarantined identities before scoped cleanup. No check grants a late observer authority from a previous generation.

D5: Tasks 1/6 cover malformed, unsupported, inconsistent and cyclic records and uncertain probes; Task 7 preserves one deadline and pre-mutation disappearance retry; Tasks 9/10 require operation-specific failures and no unsafe cleanup. Task 6 explicitly excludes age or timeout as permission to steal.

D6: Task 5 scopes release authority to the exact owner while preserving ambiguous legacy claims. Tasks 6/8 classify uncertain liveness and the current blocker, preserve store labels, and prohibit the false dead-owner-is-live message. Public result kinds remain sufficient: a handle for success, timeout for occupied/budget exhaustion, interrupted for wait interruption, recovery_refused for invalid/uncertain authority, and existing filesystem/recovery failure results for operation errors. No scenario requires inventing success for an absent/refused operation.

## Consistency and preservation sweep

Automatic clearing in staged outcome 1 means the old claim and lease are removed after validated quarantine; immutable retention during election does not contradict it. The next caller obtains an actual ownership handle rather than a success log alone.

Death-proof recovery and conservative malformed/unknown refusal apply to disjoint inputs. Bounded timeout does not authorize deletion. Legacy binding ambiguity is distinguished from a validated explicitly foreign owner; successful release in the latter scenario does not weaken the former refusal. Normal live owners still prevent recovery activity, and each task touching that path retains the owner check.

The existing store reads and writes only after lease acquisition. Task 2 names that production entry point and checks persisted field values, unchanged unrelated fields, zero writes on refusal, and protected-write concurrency. Internal claim logic therefore has a real path to Story 5 rather than merely a helper-level test. Task 1/6 checks start at acquisition on actual serialized metadata, so preclassified fake inputs do not substitute for decoding proof.

All same-resource cross-layer pairs were considered in both directions: recovering dead ownership preserves live exclusion; returning a bounded failure preserves no-write-on-refusal; owner binding preserves both replacement safety and valid release. No contradiction, oscillation, or cannot-deliver finding remains. All criterion rows use actual task-local checks, and the checks of all cited tasks are considered together.
