# Coherence: Remediation lap allowance derives from the feature's complexity tier (#2413)

**Date:** 2026-10-25
**Tier:** M
**Track:** technical. The `fr` row class is omitted because there is no PRD; the stories carry the requirement layer.
**Outcome source:** jstoup111/ai-conductor#2413 was recovered from a stale claim, and its staged `.pipeline/intake-outcomes.md` has an empty Desired outcome, so the `outcome` row class is omitted. The issue's four desired outcomes are carried by Stories 1-4 (`**Requirement:**` lines).

Story and task rows are derived from the plan's `**Story:**` lines. Criterion rows are generated from the plan's Coverage Check, which passed independent coverage judgement on every row (round 1: 34 of 37; round 2: the 3 revised rows). The `adr` rows cover the three on-main ADRs amended by #2413; each decision is dispositioned in the plan's Architecture Obligation Coverage table and judged below.

Achievability (§4g): every criterion row's cited check names its mechanism. `validatePrdAuditBlock` / `validateArchitectureReviewAsBuiltBlock` and the two `resolve*Block` functions cover config shape and non-materialization. `resolveRemediationLapAllowance` and its four wrappers cover the resolved values, including through `loadConfig`. The conductor run loop's BUILD-dispatch settlement, `planRemediation`, `refusalReworkAllowanceBlocker` and the validation-group join cover enforcement. `renderKickbackBudgetView` / `kickbackBudgetView`, the settlement and refusal halt reasons, `kickback-budget inspect` (`defaultsFor`) and `daemon status` cover rendering. The committed-config test covers this repository's config. Representable outcomes: `allowanceSource` is the closed set `default`, `configured`, `raised`, and `tier` is `S`, `M`, `L` or null. Every required scenario maps to one of those values: an unrecorded tier is null, rendered `unrecorded, treated as M`; a raise is `raised`; an unavailable entry renders no allowance at all. Input boundary: inspect reads the tier from the feature worktree's `.pipeline/conduct-state.json`, and daemon status reads the entry's `tier`, which `stateExtras` fills from the same conduct state. Halt, inspect and status therefore share one tier source, and Task 9's same-figures check proves it. Constraint sweep: no criterion requires violating an approved decision; the three amended decisions now state the tier-derived allowance the criteria require.
