# Coherence: The engine performs FINISH's PR-prose write; the provider only returns prose

Source-Ref: jstoup111/ai-conductor#3529. Tier M, technical track (no PRD, so no `fr` rows).

Outcome mapping: outcome 1 (valid prose advances `author_pr_prose` without operator action) is Story 1, where the engine publishes returned prose and the transition advances, and Story 2, where the next pass recovers after a failed one. Outcome 2 (no provider builds a GitHub request) is Story 1, where the provider writes only the handoff and the engine performs the guarded edit, and Story 4, whose prompts never mention `github-operation` or a request shape. Outcome 3 (one consistent account in `skills/finish` and `skills/pr`) is Story 4. Outcome 4 (a provider authoring failure is reported specifically) is Story 2: `prose_not_returned` and `prose_invalid`, carried into the exhaustion halt with their detail. Outcome 5 (the secondary refusal wording) is Story 5.

Consistency pass: no cross-layer contradiction. Every prose write goes through the engine (Stories 1 and 3) while re-observation stays authoritative, so a direct provider edit still advances (Story 1). That matches adr-2026-08-13 and the amended Story 3 of the #3376 spec, which keeps `publication_transition_unmoved` only for an executed engine edit that still reads placeholder. Handoff validation uses the observer's own placeholder classification, which matches `preserve-project-owned-pr-body-sections-through-fi` criterion 60.
