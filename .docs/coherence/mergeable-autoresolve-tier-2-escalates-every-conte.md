## Judgement notes

**outcome-1 is a gap, waived.** The bullet asks that any conflict where the resolver can state both intents and a verifiable choice exists be resolved without the operator. The operator narrowed delivery to conflicts confined to test code on 2026-09-20, after the architecture review found `adr-2026-08-01-rebase-full-replay-intent-validation` forbids accepting ambiguity "merely because downstream tests might pass". Production-path conflicts still escalate. Gap id: outcome-1. See the coherence waiver for this plan.

**outcome-2** is delivered by Story 1 (both happy paths) through tasks 7 and 17. **outcome-3** by Story 4 through tasks 11 and 12. **outcome-4** by Story 1 negatives (suite failure, unresolved, lease rejection; task 8) and Story 2 negatives (mixed and non-test conflicts; tasks 3, 4). **outcome-5** by Story 4 happy path 1 and its no-suite negative (tasks 8, 11): the audit comment is posted only after the suite stub returns zero and names the literal command. **outcome-6** by Story 5 through tasks 13 to 16.

**Consistency pass.** No cross-layer contradiction found. Checked in both directions: outcome-6 against the ci-fix and halt-marker negatives of Story 5 (the clear is keyed on a recorded conflict cause, so satisfying either leaves the other true); outcome-5 against Story 4's comment-failure negative (the push is published only after the suite passes, and the verdict event naming the verification is emitted before the comment is attempted, so a lost comment does not produce an unnamed verification); amended `adr-2026-06-29-rebase-conflict-resolution-dispatch` D1 against Story 3's finish-time Done-When (no declarations means unchanged results).

**Preserved-behavior sweep.** Story 2 promises unchanged strict-path and finish-time behavior. New side effects on the same path are the verdict event (task 12), the audit comment (task 11), and the residue event (task 10); each check conditions them on a validated verdict or a non-empty excused list, and task 9 asserts neither stub is called on the strict path. Task 4 asserts the prompt is byte-identical when the signal is false, and task 6 asserts unchanged guard results with no declarations.

**Achievability.** Every criterion quote names its mechanism (`classifyConflictScope`, `validateResolutionVerdict`, `runAcceptanceGuards`, `resolveConflictingPr`, `postSupersessionAudit`, `maybeClearConflictLabel`, `prMergeState`). Input boundaries: the test-only decision is produced from the real conflicted path list by task 1 and reaches the resolver through task 4 and the flow through task 7; the halt-marker input is produced from the real pull request read by task 14 and consumed by task 15; replayed shas are captured in task 7 and consumed by task 3. Closed sets: the verdict choice set (`superseded`, `merged`, `source`) represents every happy scenario, and "cannot choose" is represented by the existing unresolved result rather than a verdict value.

**Architecture obligations (4f).** Each amended ADR has one citable decision, D1, mapped as `task`. `adr-2026-08-01-rebase-full-replay-intent-validation` D1: task 4 asserts the prompt carries the exception only when the engine-set field is true, and task 17 the skill section. `adr-2026-06-29-rebase-conflict-resolution-dispatch` D1: task 6 asserts the declared, test-only excusal. `adr-2026-07-04-widen-rebase-resolution-dispatch-to-sweep` D1: task 11 asserts the audit body names the verification command and zero exit, task 12 the event. `adr-2026-07-04-autoresolve-state-and-config` D1: task 15 asserts the clear conditions, task 13 the cause field.
