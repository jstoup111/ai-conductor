## Notes

- **Coverage judgement.** An independent subagent applied `skills/coverage-binding/SKILL.md` to one claim per criterion row (the criterion text plus every cited task's `Done when` checks, nothing else). Round 1: 37 of 38 asserted. Claim 2 (Story 1 happy path 2) was refused because the check did not require the restack to proceed. Task 4's check now requires the journal and the count of 4 after `applied`, and round 2 asserted it. After Task 2's worktree-helper check was revised to read config from the main checkout, round 3 re-judged the six claims citing Task 2, and all six asserted.
- **Cross-provider review.** A read-only Codex source review found that Task 3 missed the direct `checkCascadeCap` test caller in `cascade-cap.sweepG3.realgit.test.ts`, which the production typecheck excludes. Task 3 now names it and requires `npm run typecheck:test`. Story 4's Done When now lists only the cases its tasks assert; the shared formatter's configured and unrecorded renderings are pinned in Task 2.
- **Documentation.** The `docs/reference/configuration.md` entry for `stacked_prs.max_restack_cascades` and the runbook cascade-cap text are left to the maintain-documentation pre-finish gate. A composer spec stages only `.docs/`, and `/plan` carries no documentation task.
- **Achievability (§4g).** Each cited check names its mechanism: `validateStackedPrsBlock` through `validateConfig` for config shape and non-materialization; `resolveRestackCascadeAllowance`, `resolveCascadeAllowanceForWorktree` and `loadConfig` for resolved values; `checkCascadeCap` and the `feature-repair` branch of `runRestack` for enforcement; the raise, reset and reconcile paths of `kickback-budget-cli.ts` with `applyCascadeAdjustment` for recovery; and `formatCascadeAllowance` / `renderCascadeSummary` behind the halt, inspect and `daemon status` for rendering.
- **Representable outcomes.** `source` is the closed set `default` or `configured`; a per-child raise is the separate `raised` flag; `tier` is `S`, `M`, `L` or null (rendered `unrecorded, treated as M`). An absent ref is `none charged`, and a malformed ref is `unavailable (<detail>)`. Every required scenario maps to one of those values.
- **Input boundary.** The halt, the raise and both read-only surfaces take the tier from the same feature-wide `.pipeline/conduct-state.json` and the config from the main checkout's `loadConfig`, as the dispatching executor does (#3456, #3502), through one resolver. The halt and the ref compare-and-swap therefore agree unless the config or tier changes between them, and Story 3 makes that case an explicit refusal.
- **Constraint sweep.** No criterion requires violating an approved decision. The amended `adr-2026-10-10` decision 10 states the tier-resolved bound the criteria require, and `adr-2026-10-12-routed-whole-feature-repair`'s re-validation bound stays finite.
- **Prerequisite.** The plan builds on #3475's per-originating-child restack limit model and records #3475 as a land dependency.
