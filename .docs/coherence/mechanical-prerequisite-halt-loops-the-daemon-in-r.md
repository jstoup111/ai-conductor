# Coherence: A retryable HALT is cleared before the daemon re-dispatches it (#3601)

**Stories:** .docs/stories/mechanical-prerequisite-halt-loops-the-daemon-in-r.md
**Tier:** M (technical track; no PRD, so no `fr` rows)

Every criterion row was judged by an independent coverage subagent against only the criterion and the cited tasks' `Done when` checks, and every row asserts. Achievability was checked against `adr-2026-11-07-retryable-halt-cleared-at-dispatch-boundary`. No cited check requires violating a decision. The dispatch-boundary clear never writes the over-scope decision carrier `HALT.cleared`, which is `adr-2026-08-24-over-scope-decision-block-and-durable-refusals`'s carrier (Task 8, Task 10). The HALT dispositions in play are the existing closed `HaltDisposition` set plus the fail-closed unknown string. Every input boundary (HALT-body comparison against `HALT.rekicked`, whole-feature count) is owned by a cited check (Tasks 4, 8).
