# Coherence: CLI help matches CLI behavior

Source-Ref: jstoup111/ai-conductor#1012. Tier M, technical track (no PRD, so no `fr` rows). The staged intake projection `.pipeline/intake-outcomes.md` carries no Desired-outcome bullets, so the `outcome` row class is omitted. Mapping of the issue's seven desired outcomes, for the reader: land and handoff help (Story 1); `--idle-poll` default (Story 2); operator-facing commands visible and internal ones hidden by commander's hidden mechanism (Stories 3, 4); real flags declared (Story 5); `--auto`/`--interactive` exclusion (Story 6); `register`/`create --help` (Story 7); a test asserting declared defaults equal runtime fallbacks (Story 2), plus the drift guard (Story 8).

Consistency pass: an independent contradiction sweep found one conflict on its first round — Task 3 and Story 4 would have hidden the eight Story 3 operator-facing commands — resolved in place by excluding them from the hidden set; it also surfaced that the router would replace `daemon --help`'s full subtree, resolved by making `daemon` self-owned (ADR Decision 2). The second-round sweep over the final plan, stories, and ADR decisions D1-D5 found no conflict. Task pairs sharing files (`cli.ts` in Tasks 2, 3, 8, 9, 10, 11; `cli-pre-dispatch.ts` in Tasks 1, 4, 5, 6; `test/cli/index.test.ts` in Tasks 2, 3, 9, 10) add disjoint declarations or assertions; Task 3's hidden-command skip in `renderDaemonHelp` cannot hide a daemon verb because no task declares a daemon verb hidden, and Task 10's Done-when keeps the daemon verb drift test passing unchanged. Preserved-behavior sweep: no task adds an `.action()` or changes a detector's dispatch, and the only new runtime effect on dispatch paths is the help router, which fires only when argv carries `--help` or `-h` for a router-owned registry command.
