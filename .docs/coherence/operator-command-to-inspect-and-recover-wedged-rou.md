## Outcome notes

- **outcome-1, outcome-2, outcome-4** are delivered by jstoup111/ai-conductor#3445 (spec PR #3462, merged on main,
  not yet built): the admission fence, the marker-first drain, the bounded mechanical stall HALT, and unchanged
  single-round behavior. Gap ids `outcome-1`, `outcome-2` and `outcome-4` are waived in
  `.docs/coherence-waivers/operator-command-to-inspect-and-recover-wedged-rou.md`. This spec changes no engine
  path those outcomes govern.
- **outcome-3** has two parts. The supported way is the `stack rounds` inspect and close commands, Stories 1–4.
  The documented way is the `stack rounds` CLI help (Task 9) plus the refusal and next-step text. Updating the
  `stacked-feature-manual-recovery` runbook to replace its hand-run `close-round.mts` script is left to the
  pre-finish `maintain-documentation` gate, because a spec plan carries no documentation tasks.

## Architecture-decision tie-out (§4f)

D6 (task-6, task-4, task-5): the close writes `closed` with pending hosts set to `done` in one compare-and-swap,
and the predicate refuses every other shape the amendment excludes. D7 (task-8, task-7, task-9): the CLI writer
runs under the dispatch lease after the read-only refusals, and inspect never takes the lease. D10 (task-6):
ledgers rebuilt from receipts are deep-equal across a close. D15 (task-10): the surviving round's leaf return
re-pends the leaf gates. D16 (task-1, task-10): the new member is deduplicated and drained exactly once. Every
other decision is correctly `no-change`/`existing`, because the feature touches no classification, owner, host,
reroute, cursor, append, obligation, snapshot, exit-restack or queue path, and reads the routing flag only
through `routingSettingOn`.
