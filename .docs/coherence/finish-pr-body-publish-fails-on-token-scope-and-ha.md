# Coherence: FINISH reports the real PR-publish failure instead of "pr.prose unchanged"

Source-Ref: jstoup111/ai-conductor#3376. Tier M, technical track (no PRD, so no `fr` rows).

Outcome mapping: outcome 1 (publish with a `repo`+`workflow`-only token) is outside the operator-confirmed scope boundary in `.docs/track/finish-pr-body-publish-fails-on-token-scope-and-ha.md`. The operator judged the missing `read:org` scope an operator-config issue, fixed by granting the scope, and dropped the transport change, so no story covers it and it is waived in `.docs/coherence-waivers/finish-pr-body-publish-fails-on-token-scope-and-ha.md`. Outcome 2 is Story 1 (the failure on the spine) and Story 2 (the halt reason and its events). Outcome 3 is Story 2: a pass whose recorded publish failed is classified before the fixed-point guard and never reads as unchanged. Per approved assumption A3 of adr-2026-10-24-finish-surfaces-guarded-publish-failures, `provider_attempt.outcome` keeps meaning that the provider ran. Outcome 4 is Story 3.

Consistency pass: no cross-layer contradiction. Story 2 halts only after a successful dispatch with placeholder prose re-observed, while Story 3 keeps the unchanged halt exactly when no matching failure is in the pass window, so no pass satisfies both. A failed dispatch keeps the existing retry (Story 2 last negative), matching the existing dispatch-failure stories. The CLI never writes the engine ledger for the new event (Story 1), consistent with adr-2026-08-08-pipeline-owned-closeout-timestamps D2 and amended adr-2026-10-12 D3.
