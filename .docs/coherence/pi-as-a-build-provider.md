## Outcome interpretation notes

- **outcome-2.** "Unavailable" is read as unavailable at runtime, after boot. A provider that is not installed now fails startup under ADR D4 and the adr-2026-07-20 decision 3 amendment; the operator chose this as a bug fix. An installed provider that is unavailable at runtime advances the ladder exactly as claude and codex do (task 19). Pi exhaustion (rate-limit or usage) is not classified in this feature. The operator deferred Pi auth and rate-limit signatures to a follow-up intake because BUILD never invokes a real Pi, so until then such output is an ordinary step failure (task 18).
- **outcome-5.** Configuration that selects an uninstalled pi is rejected at every entry point that dispatches provider work (ADR D8). The error is intentionally distinct from the unknown-provider error and names the provider, config path, and discovery reason (ADR D4), which meets the outcome's quality bar.
