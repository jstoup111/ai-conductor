## Notes

- **Outcome 1 scope.** The judgement reaches a project once it declares the shipped `build-review-dependency-hygiene` policy under `build_review.custom_rubrics`; this repository does so (Story 5). That opt-in is the operator-confirmed Approach B scope boundary in `.docs/track/new-dependencies-enter-the-tree-with-no-review-of-.md`. "Fails with a finding" holds because the policy directs `major` necessity, pinning, and incompatible-license findings (Story 4, Tasks 8–9) and this repository's `min_severity: minor` keeps them blocking (Story 5, Task 11). Only the unverifiable-license `nit` is advisory.
- **Outcome 2 scope.** "No cost" is delivered by withholding before source materialization, installation discovery, policy capture, cache lookup, lap gate, and dispatch (Story 2, Tasks 4–5). Identity neutrality keeps caches valid (Story 3, Task 6). Adjudicator routing for participating members is the existing custom-rubric path (Story 5, Task 10).
- **Story 4 layer.** Story 4's criteria are stated at the policy layer by operator decision (2026-11-07). The engine sends the policy text verbatim to the reviewer (`adr-2026-09-10-portable-build-review-policy` D3), so Tasks 8–9's content tests pin the reviewer's criteria. Live judgement on real diffs is exercised at SHIP.
- **Documentation.** The `docs/reference/configuration.md` entry for `paths` is left to the `maintain-documentation` pre-finish gate by operator decision. A composer spec carries no documentation task.

- **Absent member (Story 3).** Task 7 asserts the effective verdict, the step result, and the absence of a HALT file, which is the criterion's own layer.
- **Repository declaration (Story 5).** It is resolved through the real `loadConfig` and `resolveBuildReviewConfig` path. The advisory `nit` uses the existing `isBelowSeverityThreshold` order (verified: `nit` is below `minor`).
