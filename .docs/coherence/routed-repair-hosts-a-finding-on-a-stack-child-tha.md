## Outcome notes

- **outcome-1** (never hosted on a child lacking a file the task must modify): Story 1 resolves bare and partial file citations to repository files so D4 moves the host to a child holding them, and Story 3 adds the rem-block text to that evidence. Since every resolved input exists at the leaf, D4 always finds such a host.
- **outcome-2** (each part runs where its files exist, or the round refuses with a named halt): delivered by the first branch. One host per finding holds every file any part cites, because Stories 1 and 3 select it over the union of the finding's resolved files. Splitting a finding across hosts is out of scope (track marker). The refusal branch is deliberately not added: the operator chose fewer halts and more autonomy on 2026-10-31, and with the leaf as a fallback no refusal is needed. The #3445 fence keeps its `mechanical` precedence (Story 3).
- **outcome-3** (a prerequisite-path check never passes just because a directory exists): Story 1 drops directory citations from host-selection evidence, and Story 2 drops them from claim verification, including directory entries stored in route records written before this change.
- **outcome-4** (findings whose targets exist in the chosen host route as today): Story 1's exact-path criterion and Story 3's all-present criterion pin unchanged host, reason, record and marker.

## Architecture-decision tie-out (§4f)

D4 (task-3, task-2, task-4, task-5): host selection runs on resolver-backed inputs. Basename, partial and wrapped citations resolve; directory, ambiguous and unmatched citations never count; the block text joins the inputs; and the owner/host split and upward-only move are unchanged. D5 (task-7, task-8): claimed and stored paths are compared file to file, a stored directory never fails a destination, and a claim naming no file is an ordinary failed attempt. D7 (task-6): the #3445 admission fence still decides admission after routing, and normal admission writes the record and marker as before. Every other decision is correctly `no-change`/`existing`: the feature touches no entry classification, owner derivation, residue judgement, record schema, cursor, append, receipt, obligation, snapshot, exit restack, queue, event or flag.
