## Architecture obligation judgement (adr-014-otel-observability-exporter)

- **D9 (task: task-1, task-2).** Task 2's checks record the partial active point with `state` and `reason` and count every ship without a measured total; Task 1's checks carry the bounded reason on `feature_shipped`. Together they deliver the amended clause.
- **D10 (task: task-2).** Task 2's recorder check bounds both instruments' label names to the existing closed vocabulary plus configured static attributes, satisfying the closed-label rule.
- **D11 (task: task-1).** The reason rides the existing `feature_shipped` event as an additive field; no new event type is introduced.
- **D7 and D14 (task: task-2).** The missing counter is derived in the same listener from `feature_shipped` and carries `tier`, so the one-listener derivation and tier-on-every-feature-instrument rules hold for the new instrument.
- **D4 (no-change).** The handler still makes one in-memory recorder call per event; no I/O is added.
- **D1–D3, D5, D6, D8, D12, D13, D15–D20 (no-change).** Exporter packaging, wiring, failure isolation, transport, identity, static attributes, spool, and provenance are untouched by any task; the new counter inherits identity and static attributes through the existing `withIdentity` seam.
