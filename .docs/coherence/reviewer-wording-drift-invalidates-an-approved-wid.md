## Consistency and achievability assessment

Capture and reversal: Tasks 6/7 establish the original-input boundary and explicit authority rather than relying on prepared decisions. Task 10 proves capture reaches the actual pre-review entry and both re-entry routes. Tasks 4/5 preserve an ordered chain and reject foreign/stale supersession; therefore replay cannot turn an old acceptance into a new reversal. Task 21 carries valid siblings and named defects together to routing, so capture success does not imply gate success.

Legacy and shared storage: Tasks 2/8/9 retain supported source evidence and order through interrupted migration. Task 18 represents ambiguous legacy matches as uncertain, while Task 20 refuses authority without a current binding. An unknown future version is a storage error, not an empty case set. The inspected predecessor parser explicitly rejects a non-v1 envelope at remediation-case-store.ts:240; Task 2 carries a behavioral rejection check. Tasks 1/3 separate domain identity, effects, and writer selection; equal ordinals cannot transfer authority. PRD mutations and build-review mutations retain the other domain under the same lease.

Reconciliation: Task 11 consumes the real report parser, enumerates current sources, and includes accepted/refused/superseded/absent/unresolved history. Task 12 refuses complete-input overflow rather than presenting an incomplete subset as complete. Tasks 13/18 represent same-case, different, and uncertain without allowing the judge to create a decision. Exact-result reuse is an engine path before dispatch, not a fabricated fourth judge result. Tasks 19/20 invalidate stale authority on source, feature, code, decision, or contract changes. Rendering only the engine-owned projection cannot stale the input that produced it; changed reviewer evidence still does. No threshold or shared path substitutes for judgment.

Provider and retry boundaries: Tasks 14-17 preserve the single invocation path, pass the engine schema to both native adapters, and consume only final structured output. Task 13 supplies cross-reference completeness as well as shape validation. Task 19 accounts mechanical failures against the configured remediate allowance; Task 18 makes uncertain terminal for an unchanged snapshot. These rules can both hold: invalid transport/shape is retryable, a valid uncertain answer is not. No successful semantic retry is used to seek approval. Scratch teardown is covered for normal exit and each failure exit.

Completion: Task 20 produces accepted, blocking-refused, blocking-undecided, and not-blocking from current intent plus valid authority; uncertain or absent relationships can truthfully remain blocking-undecided. Task 22 requires the real regression flow to reach artifact completion and shipped-record projection, and makes missing/interrupted relations and rendering defects blocking. Thus a helper-level accepted value alone cannot satisfy the final criterion. Ordinary story-criterion authority stays mechanical and does not require NC rematching.

Preserved behavior: Task 3 explicitly preserves existing build-review no-PRD/flag-off dispatch and storage-access conditions; event Task 23 emits only PRD occurrence results, not a new side effect on the protected build-review path. Tasks 14-16 make no-schema calls retain args, streams, metering, result shape, and no schema scratch. Task 17 preserves case-v1 and gap planning; Task 21 preserves other validation members and existing FIXABLE/PLAN_GAP budgets. No new NC result represents an act/defer work effect. Within-intent and outside-harmless paths remain not-blocking without unnecessary semantic dispatch.

Observability: Task 23 owns actual offer/import/capture/coordinator producers and the emitter-to-persister-to-ledger consumer boundary. Named early errors are carried from Task 10 and parsing/reconciliation into those exits; they do not disappear behind a generic unresolved result. Detailed occurrences are persisted, while existing loop_halt supplies operator rendering, matching the existing case-lifecycle sink ownership.
