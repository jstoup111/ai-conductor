# Coherence Check: git-side veto for ref-moving destructive git that bypasses the build guard (#2693)

Date: 2026-10-03
Source: jstoup111/ai-conductor#2693
Tier: M; technical track; session-default model.
Verdict: PASS with one waived outcome — outcome-1 names a non-fast-forward move of a branch ref, which the operator scoped out on 2026-10-03; its other two classes are covered by Stories 1 and 3.

## Inputs and Judgment

This review compares the five staged intake outcomes, the amended APPROVED ADR (adr-2026-09-23-engine-git-guard-on-agent-path: D7 and D10 notes and new decisions D11–D15), 6 accepted stories, 11 plan tasks and 38 extracted criteria. The plan and this artifact are rendered from one data source, and every criterion quote is checked as an exact substring of the cited task's `Done when` block. All 38 criterion rows are identical to the plan's `## Coverage Check` rows, which an independent coverage judge passed (three rounds, 2026-10-03), so they are not judged a second time.

- **Outcome 1 is waived.** It names three ref-moving classes. Force-deleting an unmerged branch is delivered by Story 1, and a push that overwrites remote history without a lease by Story 3. A non-fast-forward move of a local branch ref (amend, rebase, `reset`, `branch -f`) was excluded by the operator during explore, because agents and the engine move refs that way routinely. The track marker's scope boundary records this. See `.docs/coherence-waivers/ref-moving-destructive-git-that-bypasses-the-build.md`.
- **Consistency (§4d).** Outcome 2 (engine rewrites unchanged) was checked against every refusing task, and preserved behaviour holds.
  - Task 2 bounds the `reference-transaction` hook to `refs/heads/` deletions and asserts that ordinary commands keep their no-hook exit status.
  - Task 10 runs the engine's exact argv, from its own working directories, through both hooks.
  - The one engine deletion that would be refused, a unique-tip `branch -D` from inside the feature worktree, is an operation the engine never performs, so no task check opposes outcome 2. D14 states this as a constraint.
- **Cross-layer oscillation.**
  - Story 2 (maintenance passes) and Story 1 (deletions refused) both turn on loose-ref deletion. Task 5 keeps them separable with the loose-file-plus-packed-value rule, and its third check asserts that packed branches stay protected.
  - Outcome 3 (lease pushes succeed) and Story 3 (explicit stale-value lease refused) were reconciled at conflict-check as an accepted degrading overlap. No engine push uses an explicit lease value.
- **Architecture tie-out (§4f).** Each obligation was judged against the amended ADR:
  - **D11** (task-1, task-9): asset provisioning and chaining.
  - **D12** (task-2 to task-5): the full deletion rule, including the prune case.
  - **D13** (task-6 to task-8): the lease-equivalent push rule.
  - **D14** (task-10, task-11): engine operations pass, and the hooks are re-verified before each dispatch.
  - **D15** (task-2, task-6): absolute-path real git with an empty `HOME`.
  - **D3** and **D7** are task obligations, because this feature extends the D3 re-verification and the D7 premise.
  - **D1, D2, D4, D5, D6, D10** are `existing`: the #1354 code shipped in fd6f539ca and is unchanged here.
  - **D8, D9** are `no-change`: the operator Bash hook and the `tdd` skill are not touched.
- **Achievability (§4g).** Every check names its mechanism and its assertion. The mechanisms are `REFERENCE_TRANSACTION_HOOK`, `PRE_PUSH_HOOK`, `writeGitHooks`, `ensureGitGuardForDispatch`, `makeGitRunner`, and the interpreter-source inventory. The git behaviours they rely on were observed on git 2.53.0 on 2026-10-03.
