Outcome-2 note: the operator decided on 2026-10-21 (explore and architecture review) that "added or changed" is delivered mechanically when the cited title sits on a line added in the task's start-to-close window. A test whose body alone changed is held for one judgement rather than closed mechanically, because a text-only check cannot attribute a body edit to a test without parsing the language (adr-2026-08-22 D6, D11). Stories 1 and 2 carry exactly that rule, so the row is covered as the operator scoped it.

Outcome-1 note: the operator-confirmed scope boundary (`.docs/track/done-when-closes-as-verified-citing-tests-that-don.md`, "Excluded: … judging tests the task itself added (a weak new test still closes mechanically)") delivers this outcome for every citation of a test the task did not write. That is the class every bad closure in the #3200 sweep came from. A test whose title the task itself added closes `verified` without judgement (Story 2). That exclusion is deliberate: outcome-2 requires such tests to close with no extra cost or delay.
