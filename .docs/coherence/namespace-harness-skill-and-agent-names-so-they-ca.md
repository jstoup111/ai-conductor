# Coherence: Skill names resolve from frontmatter (Spec 1 of #885)

**Date:** 2026-10-14
**Tier:** M
**Track:** technical. The `fr` row class is omitted because there is no PRD; the stories carry the requirement layer.
**Outcome source:** jstoup111/ai-conductor#885. Outcome rows quote the staged sanitized bullets verbatim.

This is Spec 1 of the two-spec delivery recorded in `adr-2026-10-14-ac-prefixed-skill-names` Decision 7. It makes every host-visible skill name a read of the skill's frontmatter `name:` while leaving every shipped name unchanged, so none of #885's four outcomes is observable from this spec alone; each is waived to follow-up intake jstoup111/ai-conductor#3233, which is blocked on this spec. The ADR row pool is the two non-deleted ADR files in the change set: the new ADR and the amended sandbox ADR. Criterion rows are generated from the same source as the plan's Coverage Check, which passed independent coverage judgement on every row.

Achievability (§4g): each criterion row names the mechanism that delivers it (`resolveSkillName`, `DefaultStepRunner`'s `skillNameRoot` and the daemon runner factory, the auxiliary grader/rebase dispatches, Pi's name-keyed catalog lookup, the composer/monitor/prelude launch sites, the worktree `skillOverrides` writer, `provisionProviderHome`, the sandbox `skills/` builder, `assertStepCommandsResolve`, and `bin/install`'s link, `--check` and `--uninstall` paths) and its observable assertion over a renamed fixture or the shipped tree. Constraint sweep: Story 2's directory-name fallback when the engine harness root cannot be resolved honors Decision 2's fallback rule, and Story 6's per-skill sandbox links (task-8) honor Decision 3 and the amended sandbox ADR (each link still resolves into the worktree's edited `skills/<dir>`). No criterion requires a shipped name to change, so Decision 7's no-visible-change constraint holds; Task 2's and Task 3's checks on identical shipped invocations and Task 9's check on identical shipped install listings enforce it. Story 7's install check is delivered through `bin/install --check`, which install-freshness delegates to (task-10), so the check's per-link report and exit status are the observable outcome.
