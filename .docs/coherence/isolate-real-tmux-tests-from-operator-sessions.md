# Coherence: Isolate real-tmux tests from operator sessions (#2476)

**Date:** 2026-10-03
**Tier:** M
**Track:** technical. The `fr` row class is omitted because there is no PRD; the stories carry the requirement layer.
**Outcome source:** jstoup111/ai-conductor#2476. Outcome rows quote the staged sanitized bullets verbatim.

The current spec change set contains no `.docs/decisions/adr-*.md` file (the architecture review created no ADR), so the `adr` row class is omitted. Story and task rows are derived from the plan's `**Story:**` lines. Criterion rows are generated from the same source as the plan's Coverage Check, which passed independent coverage judgement on every row (round 1: 34 of 41; round 2: 6 of the 7 revised rows; round 3: the last revised row). The consistency pass (§4d) ran through a fresh subagent over the final plan and found no contradiction. The only preserved-behavior promise, that no production module under `src/` changes behavior, holds because every new module and edit lives under `src/conductor/test/` or the three Vitest configs; the floor reaches production `daemon-tmux.ts` only through the inherited process environment. Achievability (§4g): each criterion row names the mechanism that delivers it (`installTmuxIsolationFloorSync`, `assertTmuxFloorActive`, `teardownTmuxIsolationFloor`, `createPrivateTmux` and its `dispose`, `sweepStaleTmuxRoots`, `auditTmuxAccessSource`, `findStaleAllowlistEntries`, the migrated test files) and its observable assertion. The Story 1 tier proofs rely on the verified tmux behavior recorded in the architecture review: with `TMUX` unset, the client resolves its socket under `TMUX_TMPDIR`.
