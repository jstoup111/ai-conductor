# Complexity: Refusing a newly raised OVER_SCOPE criterion halts as malformed-history

Tier: M

Rationale: Four production files change. `capturePrdWideningDecisions` in `src/conductor/src/engine/prd-widening-capture.ts` stops treating a cleared block as all-offer or all-legacy and decides capture scope per entry: a story-criterion entry without an offer reference is captured with criterion-only scope, while an NC entry still requires its persisted offer; each defect also carries the entry's criterion. The capture-defect-to-recovery mapping in `src/conductor/src/engine/conductor.ts` (currently a fallthrough to `malformed-history`) becomes a total per-kind mapping, `src/conductor/src/engine/prd-widening-entry.ts` passes the offered story-criterion set read from the persisted PRD-audit verdict into capture, and `src/conductor/src/engine/prd-widening-recovery.ts` gains the recovery reasons and actions those kinds need. No new module, store, schema, event type, CLI flag, or case-store record. It is Medium rather than Small because it changes which cleared entries become operator authority under which scope, a rule written in APPROVED `adr-2026-09-07-durable-prd-widening-decision-reconciliation` D3/D4, which must be amended, and because it changes operator-facing halt recovery text. Risk is bounded to over-scope halt clearing and is covered by capture unit tests and the existing conductor PRD-widening entry tests.
