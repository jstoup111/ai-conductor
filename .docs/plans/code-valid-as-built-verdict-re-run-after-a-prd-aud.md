# Implementation Plan: Code-valid as-built verdict re-run after a prd_audit refusal halt

**Date:** 2026-10-22
**Design:** none (technical track, Tier S — see `.docs/track/code-valid-as-built-verdict-re-run-after-a-prd-aud.md`)
**Stories:** .docs/stories/code-valid-as-built-verdict-re-run-after-a-prd-aud.md
**Conflict check:** Not required (Tier S)

## Summary

Stop the auto-mode SHIP validation group from re-judging a sibling whose verdict is still good. Every
judgement halt of the group join keeps the siblings it found satisfied, as its no-verdict and
mechanical-fault exits already do, and the group fan-out runs the serial walk's existing
stale-preservation probe before dispatching a `stale` member. Three tasks, all in
`src/conductor/src/engine/conductor.ts` plus tests.

## Technical Approach

- **Verified current behavior (local main `7aa1bba459`).**
  - `recordGroupRefusal` (`conductor.ts`) commits `refused` for the judging step and any `refusedSteps`, plus `last_step`. It writes nothing for the other dispatched members. Its six callers are all inside the validation-group join of the auto-mode fan-out: the `prd_audit` plan-gap and over-scope halts, the as-built kickback no-op escalation halt, the as-built remediation-planner halt (`remediationOutcome.kind === 'halt'`), the as-built terminal halt, and the generic group halt.
  - The remaining judgement-halt exits persist no member status at all: the `prd_audit` decision-projection halt (`prdAuditRoute?.kind === 'projection-halt'`); the refusal-rework halts (`haltGroupedRefusalRework`, which writes through `writeRefusalReworkHalt` / `writeRefusalReworkAllowanceHalt`); the gap-member kickback no-op escalation halt (the `checkKickbackToBuildEscalation(gapName)` loop over `gapMemberNames`); the two gap remediation-planner halts (`remediationOutcome.kind === 'halt'` in the merged manual_test work-order branch and in the gaps-only branch); and the `manual_test` FAIL kickback halts the join reaches through the shared `handleManualTestFailKickback` closure (no-op escalation, routed-admission `exhausted`/`halted`, self-heal exhaustion, and the `stopIfPrMerged` durable-shipment mechanical halt), each of which returns `{ action: 'return' }`. The join calls that closure at three sites: the `siblingsSatisfied` branch, the merged work-order branch's `remediationOutcome.kind === 'none'` fallback, and its spent-budget fallback. At the two fallbacks a gap member is unsatisfied, but a third member can still be satisfied (for example `manual_test` FAIL rows, a FIXABLE `prd_audit`, and an APPROVED `architecture_review_as_built`).
  - `checkKickbackToBuildEscalation` is a closure inside `run()`, not an instance method, so tests cannot spy on it. Existing tests reach its no-op halt with a real second lap (`conductor-groups-and-signals.test.ts`, `conductor-verdicts-and-daemon.test.ts`): a first round routes the gap back to `build`, BUILD makes no commit, and the second round's unchanged failing verdict triggers the halt. `admitRoutedManualTestKickback` is an instance method and can be stubbed.
  - A member whose dispatch fails, or whose verdict handshake keeps failing, exhausts its branch retries and settles `no-verdict` (`group-core.ts`), and the no-verdict exit is checked before every judgement-halt exit. So at a judgement halt, a non-satisfied sibling is one with an unsatisfied gate verdict or, for `manual_test`, FAIL rows.
  - The typed as-built completion predicate preserves a code-valid verdict even with `gate_code_validity.enabled: false` (the existing `stale-gate-predispatch.acceptance.test.ts` case "preserves a code-valid typed as-built verdict with gate code validity disabled"); `prd_audit` and `manual_test` honor the kill switch. The fan-out reuses the same predicate, so it inherits exactly that per-gate behavior.
  - The no-verdict and mechanical-fault exits already build a retention map inline: for every dispatched member other than the failed one where `memberSatisfiedAtJoin(idx)` holds, they write `[member]: 'done'` and `` [`${builtinGroup.name}__${member}`]: 'done' `` in the same `commitStateChanges` call as the failure. This is the approved behavior of adr-2026-07-10-validation-group-join D2 as amended by #1425: the retained `done` stays subject to kickback restaging and to the FINISH fence (`nonGreenFinishValidators`) re-validating every member at current HEAD.
  - On resume, `resolveGroupMembership` (`resume-entry.ts`) treats a `done` member as already passing and dispatches every other non-skipped member. A `stale` or `pending` sibling is therefore always re-dispatched.
  - The serial walk's stale-preservation probe (the `currentStatus === 'stale' && step.preservableOnStale && this.verifyArtifacts && !explicitlyTargeted` block, #2639) runs only for the step the walk is visiting. When the group engages at its entry member, later members are dispatched inside that fan-out and never reach their own walk iteration, so they are never probed. The probe calls `checkStepCompletion(..., { ...completionCtx, preserveProbe: true })`, emits `verdict_freshness` when the outcome is `preserved_surface_miss`, and saves the step `done`.
  - The daemon never sets `fromStep` (only the CLI `--from` does), and per-member artifact sweeps happen at member dispatch (`group-core.ts`), so a pre-dispatch probe sees the stored verdict intact.
- **Retention (Story 1).** Add one module-level pure function in `conductor.ts`, `satisfiedSiblingRetention(groupName, satisfied, excluded)`. It returns `{ [m]: 'done', [`${groupName}__${m}`]: 'done' }` for each member in `satisfied` that is not in `excluded`. The no-verdict and mechanical-fault exits switch to it with no behavior change. `recordGroupRefusal`'s input gains a required `satisfiedMembers: readonly StepName[]`. It resolves the group from `getGroupForStep(input.groupStep)` and merges `satisfiedSiblingRetention(group.name, satisfiedMembers, refused)` into the change set it already commits, so the retention and the refusal land in one commit. The field is required on purpose: a future caller must state which members were satisfied or it does not compile. Inside the fan-out, a closure `satisfiedAtJoinMembers()` lists `membership.dispatchable` filtered by `memberSatisfiedAtJoin`, and every `recordGroupRefusal` call passes it. The projection halt and `haltGroupedRefusalRework` commit `satisfiedSiblingRetention(builtinGroup.name, satisfiedAtJoinMembers(), new Set(['prd_audit']))` through `commitStateChanges` before their existing `persistPendingStateChanges`. The gap no-op escalation halt and both gap remediation-planner halts commit `satisfiedSiblingRetention(builtinGroup.name, satisfiedAtJoinMembers(), new Set(gapMemberNames))` (the merged work-order halt also excludes `manual_test`) through `commitStateChanges` immediately after their `writeHaltMarker`. At each of the join's three `handleManualTestFailKickback` call sites, when it returns `{ action: 'return' }`, commit `satisfiedSiblingRetention(builtinGroup.name, satisfiedAtJoinMembers(), new Set(['manual_test']))` before returning (the filter already drops unsatisfied gap members); its `continue` (BUILD kickback) path is unchanged, and the shared handler itself, which the serial walk also uses, is not modified. The all-green findings-projection halt and the dispatch-fault halts (authentication park, permission denial, cached-login trial) are out of scope and unchanged.
- **Fan-out preservation (Story 2).** Extract the serial probe into one private method, `preserveStaleJudgedGate(state, stepDef, explicitlyTargeted, emit)`. It returns `true` when it preserved the step: `verdict_freshness` emitted and the status saved `done`. Any thrown error or a not-preserved result returns `false`. The serial walk calls it in place of the inline block. In the validation-group engagement block, before `resolveGroupMembership`, call it for each member of `builtinGroup.members` other than `step.name` whose persisted status is `stale`, passing `explicitlyTargeted = this.fromStep === member`. The step being visited is skipped because the walk already probed it this iteration. `resolveGroupMembership` then sees preserved members as `done`. Members that are `failed`, `refused`, or `pending` are never probed. No new event variant: the existing `verdict_freshness` event is the observation, matching #2639 Story 3.
- **Width-one rejoin.** A preserved member is saved with its bare key only, the same state shape the serial probe already produces when it preserves `manual_test`. Whether the remaining single dispatch runs as a retained-sibling rejoin or as the serial baseline is still decided by the existing `hasRetainedValidationSibling` rule.
- **Coordination.** The spec for jstoup111/ai-conductor#3287 is landed on main and its build is in flight as draft PR #3373. That build adds a halting-step argument at these same join exits, adds `recordGroupRefusal` calls to the two gap remediation-planner halts, and adds FAIL-row `manual_test` to `asBuiltGroupRefusedSteps`. None of that changes which members `memberSatisfiedAtJoin` accepts. The changes compose: whichever lands second passes both its argument and `satisfiedMembers` (the required field makes a missed caller fail to compile), and a retention commit beside a `recordGroupRefusal` that also retains is idempotent because `commitStateChanges` drops unchanged fields.

Local test pattern: `src/conductor/test/engine/step-refusal.test.ts` drives a real `Conductor.run()` over a seeded SHIP state in auto mode and asserts persisted `step_refused`/`loop_halt` events through `EventPersister`. `src/conductor/test/engine/stale-gate-predispatch.test.ts` mocks `checkStepCompletion` (via `vi.mock` of the artifacts module) to drive the probe deterministically. `src/conductor/test/acceptance/stale-gate-predispatch.acceptance.test.ts` seeds real typed verdicts (`persistPrdAuditVerdict`, `persistAsBuiltVerdict`, the as-built code-stamp sidecar) in a real git repo. `src/conductor/test/engine/validation-group-handshake-retry.test.ts` and the no-verdict retention case in `src/conductor/test/engine/conductor-groups-and-signals.test.ts` show auto-mode group fixtures. Allowed variation: stub private routing methods (`routeCurrentPrdAudit`, `planRemediation`, `verdictDispatchHandshake`) with `vi.spyOn(conductor as any, ...)` when a real verdict fixture is impractical. Follow `.agents/skills/write-tests/SKILL.md` §3: pre-resolve unrelated steps, and end each run right after the observation with an expected sentinel (for example a runner failure on the next unrelated step) rather than a timeout.
