# Implementation Plan: Support Astra in the daemon

**Status:** Approved

**Tier:** M

## Summary

One implementation task enrolls Astra in automatic pricing refresh with focused regression coverage. Existing behavior provides compatibility evidence, not separate verification work.

## Technical Approach

Add immutable provider-keyed opt-in model metadata beside the built-in policies in provider-model-policy.ts and union it into rateCardModelIds(). The existing dispatchRateCard consumer then includes gpt-6-astra on ordinary refresh without additional model arguments. Leave configuration parsing, dispatch, retry/fallback ladders and pricing arithmetic unchanged.

Reuse the rate-card CLI fixture's real command parsing and refresh implementation, temporary output directory, injected fetch and fixed clock. The RED assertion is that ordinary refresh includes Astra when the fake upstream publishes its rates. Group repeated-refresh and missing-rate cases into this behavior's regression coverage; reuse existing whole-refresh failure tests. No full daemon run, new provider, model-validation allowlist, live service probe, or price-schema change is required.

## Existing compatibility evidence

The operator explicitly approved removing separate verification tasks. Stories 1, 2, 3 and 5 describe existing generic behavior; retain their acceptance contract using these source/test proofs. Do not create tests merely to substitute one opaque model string for another.

- Stories 1 and 2: resolveProviderNativeStepConfig uses an unchanged nullish-coalescing precedence chain. The auxiliary policy resolvers preserve authored model overrides. Existing resolved-config and provider-model-policy tests cover precedence, independent rubric configuration and exhaustive default policy; escalation.test.ts covers off-order models, caps and disabled escalation.
- Story 3: model-availability.ts treats off-ladder models uniformly. provider-execution.test.ts already covers complete native model exhaustion, actual-provider candidate options, recovery failures without advancement/cache mutation, and ordered attempt attribution.
- Story 5: rate-card.test.ts covers weighted priceUsage and applyRateCard precedence/missing-rate outcomes; codex-provider-cost.test.ts exercises dispatch pricing with an injected process and card loader; provider-execution.test.ts covers fallback usage attribution.
- These unchanged production paths and their existing tests discharge preservation checks in Task 1. Review their existing evidence while implementing the change; do not turn them into independent completion tasks or require new production edits. Run only relevant scoped checks; the configured aggregate gate provides full-suite evidence later.

Accepted stories and architecture are present. Work in the isolated feature worktree with matching package dependencies. Use ai-conductor scoped-run for RED/GREEN on the rate-card CLI test selector. Follow the repository test-inclusive typecheck and lint policy for changed tests. Temporary fixture state and asynchronous cleanup remain bounded. Account entitlement and published Astra prices are not assumed.

## Tasks

### Task 1: Register opt-in Astra for ordinary pricing refresh
**Story:** Story 4
**Story:** Story 1 — preserved compatibility
**Story:** Story 2 — preserved compatibility
**Story:** Story 3 — preserved compatibility
**Story:** Story 5 — preserved compatibility
**Type:** infrastructure
**Dependencies:** none
**Files:** `src/conductor/src/engine/provider-model-policy.ts`, `src/conductor/test/engine/rate-card-cli.test.ts`

**Steps:**
Write the RED case through detectRateCardCommand and dispatchRateCard with no --model extras, an isolated temporary card directory, and injected upstream JSON containing valid Astra and existing-model rates. It must fail because ordinary refresh currently omits Astra. Extend provider-model-policy.ts with an immutable provider-keyed opt-in model collection containing Codex gpt-6-astra; union it into rateCardModelIds using its existing deduplication and self-reporting-provider exclusion. Do not use it as an input-validation allowlist or add Astra to step defaults, tier overrides, escalation or fallback ladders. Extend the same CLI fixture to repeat refresh, change the injected Astra rate, omit or malform that rate, reject fetching, supply malformed JSON and supply no usable requested rates. Preserve the current warning and prior-card behavior. These are injected rates, not a claim about current published prices. The normal existing maintenance workflow subsequently includes Astra whenever the existing upstream source publishes usable pricing; no live fetch or newly invented production rate is needed for these tests. Run scoped RED/GREEN and commit the implementation with its refresh proof.

**Done when:**
1. dispatchRateCard invoked with a parsed refresh command and no extra models writes valid upstream Astra rates alongside existing models, retains Astra across repeated refreshes, and adopts a changed published Astra rate.
2. dispatchRateCard names Astra as missing for absent or malformed upstream Astra rates without fabricating a price, and leaves the prior card byte-for-byte unchanged on fetch failure, malformed payload or no usable requested rates.
3. rateCardModelIds includes gpt-6-astra exactly once from immutable provider-keyed opt-in metadata while preserving existing priced models, self-reporting provider exclusion, and every default step, tier, escalation and fallback policy value.
4. Existing resolver, provider-policy and escalation behavior is preserved: opaque configured Astra and effort follow current precedence and auxiliary overrides; actual model and ordinary failures are retained; default step/tier choices and fallback orders are unchanged; retries retain Astra with bounded effort and disabled escalation unchanged, and do not promote Sol to Astra.
5. Existing ModelAvailability, executeProviderCandidates and CodexProvider pricing behavior is preserved: default and explicit fallback order, empty/exhausted ladders, Claude-native fallback settings, recovery-signal precedence, actual-model diagnostics and rates, token-category pricing without reasoning double charge, provider-cost precedence, and missing-rate or missing-usage metering states remain as defined by the accepted stories.
